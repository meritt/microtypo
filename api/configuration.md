# Конфигурация

Вся конфигурация — единый объект, передаваемый в `microtypo(text, config)` или `new MicroTypo(config)`. У неё три уровня, которые свободно сочетаются: **направление** (`html`, `entities`, `input`, лимиты), **правила** (`rules`) и **вывод разметки** (`render`).

```js
microtypo(text, {
  html: false,
  entities: false,
  input: 'text',
  maxInputLength: 30_000,
  maxProcessingMs: 5_000,

  rules: {
    quote: false,
    nbsp: false,
    'number.fraction': false,
    'abbr.*': false
  },

  render: {
    paragraphs: false,
    autolink: true,
    breakline: false,
    nowrap: 'span',
    hanging: 'style',
    prefix: false
  }
});
```

Некорректные значения выбрасывают `MicroTypoConfigError` при создании; сообщение перечисляет все найденные проблемы разом. В примерах ниже неразрывные пробелы стоят там, где их ставит движок.

## 1. Направление

| Ключ              | Тип              | По умолчанию | Значение                                                                                                             |
| ----------------- | ---------------- | ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `html`            | bool             | `false`      | главный переключатель разметки. `false` — только текст; `true` — `<span>`, `<a>`, выравнивание и `<p>`, см. раздел 3 |
| `entities`        | bool             | `false`      | `false` — обычный Unicode (`«`, `—`, `…`); `true` — именованные HTML-сущности. Независим от `html`                   |
| `input`           | string \| object | `'text'`     | формат ввода и защита шаблонных разделителей — см. [ниже](#input-строка-и-объект)                                    |
| `maxInputLength`  | int              | `30_000`     | отклонять более длинный ввод (`ERR_MICROTYPO_INPUT`); ограничен сверху `5_000_000`                                   |
| `maxProcessingMs` | number           | `5_000`      | бюджет по времени между стадиями (`ERR_MICROTYPO_BUDGET`); `0` отключает                                             |
| `presets`         | bool             | `true`       | `false` не регистрирует встроенные группы правил; слой защиты и восстановления продолжает работать                   |

`input` и `presets` задаёт только конструктор: от них зависит набор сканеров и групп правил, который собирается один раз. О лимитах и ошибках — в [Безопасности](security.md).

## input: строка и объект

Строковая форма задаёт только формат, объектная добавляет защиту шаблонных разделителей и выбор полей:

```js
microtypo(text, { input: 'markdown' }); // то же, что { input: { format: 'markdown' } }
microtypo(text, { input: { format: 'markdown', template: 'handlebars' } });
```

| Ключ       | Тип      | По умолчанию | Значение                                                                                                           |
| ---------- | -------- | ------------ | ------------------------------------------------------------------------------------------------------------------ |
| `format`   | string   | `'text'`     | `'text'` \| `'html'` \| `'markdown'` \| `'json'` \| `'xml'` \| `'yaml'` \| `'toml'` \| `'frontmatter'`             |
| `template` | string   | `'off'`      | защита разделителей: `'off'`, `'handlebars'`, `'mustache'`, `'twig'`, `'jinja'`, `'nunjucks'`, `'liquid'`, `'erb'` |
| `fields`   | string[] | —            | только для `json`/`yaml`/`toml`/`frontmatter`: список разрешённых путей                                            |
| `exclude`  | string[] | —            | только для `json`/`yaml`/`toml`/`frontmatter`: список исключённых путей                                            |

Форматы `'text'` и `'html'` ведут себя одинаково: сохраняют HTML-комментарии байт-в-байт и не типографируют содержимое `<pre>`, `<code>`, `<script>`, `<style>`, `<kbd>`, `<samp>`, `<var>`, `<tt>` и `<textarea>` (его содержимое — значение формы, а не проза). Незакрытый комментарий или тег из этого списка защищает текст до конца документа — так его читает браузер; недописанный тег, у которого до конца текста нет закрывающей `>`, сохраняется целиком. Абзацы и `<br>` закрываются перед таким хвостом и не ставятся внутри или после него. Список расширяется методом `addSafeTag(tag)` — см. [Расширение](extending.md). Границы тега читаются по правилам HTML: кавычка открывает значение атрибута только после `=`, а тег заканчивается первой `>` вне кавычек; комментарий заканчивается на `-->`, какие бы кавычки в нём ни стояли. `<` вплотную перед буквой открывает тег, как в браузере: в прозе пишите `a < b` или `a &lt; b`. В Markdown и значениях форматов данных `<` вне кавычек раньше `>` означает, что тега здесь нет: `x<y` остаётся текстом. Сам тег и значения атрибутов не типографируются ни в одном формате. Форматы данных типографируют только свой текст, оставляя структуру нетронутой: значение — фрагмент, а не документ, поэтому незакрытый тег или комментарий в нём защищает только себя.

Отступ в начале строки — пробелы и табуляции перед её первым непробельным символом — в `'text'` и `'html'` считается вёрсткой автора (стихи, вложенность HTML-исходника) и сохраняется байт-в-байт. Текст за отступом типографируется так же, как без него; внутри строки пробелы схлопываются как обычно. Строка из одних пробелов отступом не считается. Края документа обрезаются: пустые строки в начале и в конце и замыкающие пробелы уходят, отступ первой непустой строки остаётся. При `html: true` абзацы и `<br>` обрабатывают отступ как обычные пробелы в начале строки: на границе блока перевод строки становится пустой строкой между блоками, и отступ уходит вместе с ним.

```js
microtypo('Строка\n    стих - тут\n\tещё  строка'); // 'Строка\n    стих — тут\n\tещё строка'
microtypo('<ul>\n  <li>Один</li>\n</ul>', { input: 'html' }); // без изменений
```

### Шаблонные разделители

`template` защищает байт-в-байт участки, ограниченные разделителями шаблонного движка (`{{ … }}`, `{% … %}`, `{# … #}`, `<% … %>` в зависимости от движка), до запуска любого правила. Закрывающий разделитель ищется с учётом строковых литералов: `}}` или `%}` внутри строки в кавычках не закрывает участок раньше времени. Работает с любым `format`, включая строковые значения форматов данных.

```js
microtypo('Здравствуй, {{ name }}. Это "Амбер".', { input: { template: 'handlebars' } });
// 'Здравствуй, {{ name }}. Это «Амбер».'
```

### Markdown

Типографируется проза; разметка CommonMark сохраняется байт-в-байт:

- ограждённые блоки (` ``` `, `~~~`) целиком, вместе с информационной строкой;
- участки кода в строке с разделителем любой длины: участок закрывается серией ровно той же длины, незакрытая серия остаётся обычным текстом;
- блоки с отступом — четыре пробела или табуляция в начале строки, но только если ей предшествует пустая строка, начало документа или другая строка кода; иначе строка — продолжение абзаца или вложенный пункт списка и типографируется;
- HTML-комментарии `<!-- … -->`; незакрытый комментарий или тег `<pre>`, `<script>`, `<style>`, `<textarea>` в начале строки защищает текст до конца документа, внутри строки или кода — нет. Закрытый такой тег защищает текст до своего закрывающего тега, остаток строки за ним типографируется; если на строке стоит только закрывающий тег другого из четырёх, строка защищается до конца;
- тег внутри кода (строчного, ограждённого или с отступом) или шаблонного выражения остаётся текстом: он не открывает и не закрывает защиту `<pre>`, `<code>`, `<script>` и других и не образует пару с тегом снаружи. Обратная кавычка внутри такого элемента или комментария тоже текст и не открывает участок кода: участок принадлежит тому, что открылось раньше;
- определения ссылок (`[метка]: цель "заголовок"`) целиком; определение сноски (`[^1]: …`) — проза и типографируется;
- цель и заголовок ссылки внутри `](…)`, маркеры списков (включая вложенные и внутри цитаты `> - …`) и жёсткий перенос из двух пробелов;
- отступ в начале строки: два пробела удерживают абзац внутри пункта списка, поэтому схлопывание пробелов до них не доходит. Внутри строки пробелы схлопываются как обычно.

````js
microtypo('- Корвин - принц\n  - Рэндом ```a - b``` тут', { input: 'markdown' });
// '- Корвин — принц\n  - Рэндом ```a - b``` тут'
````

`html: true` в этом формате даёт только строчную разметку: `paragraphs` и `breakline` по умолчанию выключены — см. [Вывод разметки](#3-вывод-разметки).

### JSON

Типографируются строковые **значения**; ключи и нестроковые значения не затрагиваются. Декодирование и повторное экранирование идут через `JSON.parse`/`JSON.stringify`, поэтому результат остаётся валидным JSON. Весь документ предварительно проверяется `JSON.parse`: некорректный JSON выбрасывает `MicroTypoInputError`.

```js
const src = '{"title":"Амбер - город","note":"Корвин - принц"}';

microtypo(src, { input: { format: 'json' } });
// '{"title":"Амбер — город","note":"Корвин — принц"}'

microtypo(src, { input: { format: 'json', fields: ['title'] } });
// '{"title":"Амбер — город","note":"Корвин - принц"}'
```

Синтаксис пути в `fields`/`exclude`:

- **образец без точки** совпадает с последним сегментом пути на любой глубине: `'title'` совпадает и с `title`, и с `posts.0.title`;
- **образец с точками** совпадает с полным путём сегмент-в-сегмент; `*` — ровно один сегмент: `'posts.*.body'` совпадает с `posts.0.body`, но не с `posts.0.author.body`; пустой ключ — тоже сегмент: `'.title'` совпадает с `title` внутри ключа `""`, но не с корневым `title`;
- **образец с ведущим `/`** — [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) (`/a/b`, с `~1`→`/` и `~0`→`~`): сопоставляется по фактической структуре документа, а не по строке пути.

Точечный путь неоднозначен, если ключ содержит `.` или является числовой строкой (`{"a.b": 1}` и `{"a": {"b": 1}}` дают один путь `a.b`). Это селектор удобства, а не граница безопасности для недоверенных данных.

### XML

Типографируются **текстовые узлы** элементов. Всё остальное сохраняется байт-в-байт: теги, атрибуты, комментарии, секции CDATA, инструкции обработки, DOCTYPE и ссылки на сущности (`&amp;`, `&#160;`, `&nbsp;`). Ведущие и замыкающие пробелы документа сохраняются. Перед типографированием проход по стеку тегов отклоняет несовпадающую или незакрытую пару тегов, закрывающий тег, в котором после имени стоит что-то кроме пробелов, незакрытую кавычку атрибута и незавершённые конструкции `<!--`, `<![CDATA[`, `<?` и `<!DOCTYPE` (`MicroTypoInputError`).

```js
microtypo('<rss><channel><title>Амбер - вечный город</title></channel></rss>', {
  input: { format: 'xml' }
});
// '<rss><channel><title>Амбер — вечный город</title></channel></rss>'
```

Грамматика сама определяет текстовые узлы, поэтому `fields`/`exclude` для XML принимаются, но ничего не делают. Поддеревья элемента с `xml:space="preserve"` сохраняются целиком: атрибут распознаётся по своему имени (чужое пространство имён защиту не включает) и по значению после раскрытия числовых и пяти предопределённых ссылок. DTD не читается, поэтому `preserve`, заданный только объявлением атрибута, не учитывается.

Защищённые теги действуют и здесь, по имени элемента: `<code>` или `<script>` в вашей схеме сохраняется байт-в-байт так же, как в HTML, и отключить эту защиту нельзя. Имя элемента должно начинаться с буквы Unicode, `_` или `:` — это строже продукции `NameStartChar`, поэтому `<😀>` элементом не считается и обрабатывается как текст.

### YAML

Типографируются **значения** — в кавычках, голые и блочные. Ключи и структура документа (отступы, комментарии, маркеры `---`/`...`) сохраняются байт-в-байт; ключ явной пары (`? ключ` / `: значение`) — тоже ключ.

- голые скаляры — только если значение — строка: скаляр, который YAML разбирает как число, дату, время, логическое значение или `null` (`100644`, `2001-12-14`, `190:20:30`, `no`, `~`), пропускается, как и скаляр с якорем, тегом или переносом на следующую строку. После прогона результат должен остаться одним голым скаляром: если в нём появился `: `, ` #`, перенос строки или открывающий индикатор в первой позиции, возвращается исходный вид;
- блочные скаляры (`|`, `>`) — построчно: отступ и заголовок блока (`|-`, `|+`, `|2`) не трогаются, поэтому границу блока правка сдвинуть не может;
- якоря, псевдонимы и теги (`&x`, `*x`, `!!str`) остаются нетронутыми; строка с любым экранированием (`\` в двойных кавычках, `''` в одинарных) пропускается.

Коллекции потока (`[…]`, `{…}`) разбираются как структура: скаляры в кавычках внутри них типографируются, ключи и сама структура остаются байт-в-байт.

```js
microtypo('title: "Амбер - вечный город"\ntags: ["Тень - Арден"]', { input: { format: 'yaml' } });
// 'title: "Амбер — вечный город"\ntags: ["Тень — Арден"]'
```

Если типографированное значение содержит собственную обрамляющую кавычку — например `”` или `&#34;`, свёрнутые нормализацией к ASCII `"`, — скаляр возвращается в исходном виде: иначе он закрылся бы раньше времени. В худшем случае значение остаётся нетипографированным, но данные не повреждаются.

`fields`/`exclude` используют тот же синтаксис пути, что и [JSON](#json), с индексами последовательности как сегментами (`tags.0`, `court.king`). Ключ входит в путь так, как записан: `0x10:` — это `/0x10`, `TRUE:` — `/TRUE`. Значение под ключом с нестроковым тегом (`!!int 0x10:`, `? !!null`) и под явным ключом, который не записан одним скаляром в строку (`? |`, `? [a]`, `{ ? [a] : v }`), селекторы, включая `/`, не выбирают и не исключают: оно типографируется только без `fields` и `exclude`. Незакрытая коллекция потока или лишнее содержимое после скаляра в кавычках выбрасывают `MicroTypoInputError`.

### TOML

Типографируются **значения** строк; ключи, комментарии (`#`) и структура таблиц сохраняются байт-в-байт:

- литеральные строки (`'…'`, `'''…'''`) типографируются всегда;
- базовые строки (`"…"`, `"""…"""`) — только если в них нет экранирования `\`.

Внутри `"""…"""` одна или две кавычки подряд допустимы и сохраняются; строка остаётся исходной, только если результат содержит сам трёхсимвольный ограничитель. Строчные массивы и строчные таблицы разбираются как структура. Как и в YAML, строка, чей типографированный вид содержит собственную обрамляющую кавычку, возвращается в исходном виде.

```js
microtypo('title = "Амбер - вечный город"\ntags = ["Тень - Арден"]', { input: { format: 'toml' } });
// 'title = "Амбер — вечный город"\ntags = ["Тень — Арден"]'
```

`fields`/`exclude` — тот же синтаксис пути, что и [JSON](#json); каждое `[[array-of-tables]]` индексируется от 0, элементы строчного массива — тоже. Незакрытые литерал, заголовок таблицы и строчная коллекция, пустой сегмент ключа, а также лишнее содержимое после значения выбрасывают `MicroTypoInputError`.

### Front-matter

Документ, открывающийся заголовком YAML или TOML, за которым идёт тело Markdown. Первая строка задаёт грамматику: `---` открывает заголовок YAML (закрывается `---` или `...`), `+++` — заголовок TOML (закрывается `+++`). Заголовок типографируется как самостоятельный документ [YAML](#yaml) / [TOML](#toml) (`fields`/`exclude` применяются к нему), тело — как документ [Markdown](#markdown). Строки-разделители сохраняются байт-в-байт.

```js
microtypo('---\ntitle: "Амбер - вечный город"\n---\n\nКорвин вернулся - домой.', {
  input: { format: 'frontmatter' }
});
// '---\ntitle: "Амбер — вечный город"\n---\nКорвин вернулся — домой.'
```

Если первая строка не `---` и не `+++`, заголовка нет и весь документ типографируется как тело Markdown. Открывающий разделитель без совпадающего закрывающего выбрасывает `MicroTypoInputError`.

## 2. Правила

Все правила типографики включены по умолчанию, кроме перечисленных [ниже](#правила-выключенные-по-умолчанию). Значение каждого ключа — логическое; ключ записывается в одной из трёх форм:

- **имя группы** — `quote`, `dash`, `symbol`, `punctuation`, `number`, `space`, `abbr`, `nobr`, `date`, `hanging`, `other`, `text` — переключает всю группу;
- **семантический набор** — раскрытие «одна концепция → несколько правил» (ниже);
- **точный идентификатор или маска** — `number.fraction`, `abbr.*`, `quote.close`.

Ключи применяются в порядке вставки, поэтому отключение маской с последующим точным включением работает как написано:

```js
microtypo(text, {
  rules: {
    'punctuation.*': false,
    'punctuation.ellipsis': true,
    'punctuation.period_at_end': true
  }
});
```

Имена групп регистронезависимы. Полный каталог идентификаторов — в [Правилах](rules-reference.md). Селектор проверяется по каталогу: `'quote.typo'` выбрасывает `MicroTypoConfigError`, а `'quote.*'` принимается, если совпадает хотя бы с одним идентификатором.

### Семантические наборы

Набор заводится только для концепций, которые нельзя выразить одним `группа.правило`:

| Набор      | Раскрывается в                                                                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nbsp`     | `nobr.nbsp_*` + `space.nbsp_*` + `abbr.nbsp_*` + `number.nbsp_*`                                                                                                                            |
| `emdash`   | `dash.em` + `dash.em_*` (`em_line_start`, `em_after_sentence`, `em_double_hyphen`; не `emphatic_particle`)                                                                                  |
| `endash`   | `dash.en_range` + `number.en_range`                                                                                                                                                         |
| `triads`   | `number.thin_space_triads` + `other.split_triads`                                                                                                                                           |
| `units`    | `abbr.nbsp_unit` + `abbr.nbsp_weight_unit` + `abbr.nbsp_volume_unit` + `abbr.nbsp_time_unit` + `abbr.nbsp_data_unit` + `abbr.nbsp_frequency_unit` + `abbr.nbsp_css_unit` + `abbr.nbsp_volt` |
| `currency` | `abbr.currency` + `abbr.nbsp_money_magnitude` + `abbr.nbsp_currency_prefix`                                                                                                                 |

### Настройки кавычек

`quote.nested` и `quote.inch` — настройки, а не отдельные правила; оба читаются обработчиком `quote.nested`:

| Ключ           | По умолчанию | Эффект при `false`                                                        |
| -------------- | ------------ | ------------------------------------------------------------------------- |
| `quote.nested` | включено     | сохранять вложенные `«…»` вместо переписывания в `„…“`                    |
| `quote.inch`   | включено     | не превращать `"` после цифры в знак дюйма `″`: кавычка остаётся кавычкой |

### Правила, выключенные по умолчанию

Включаются через `rules: { 'группа.правило': true }`. `hanging.quote`/`hanging.bracket` дополнительно требуют `html: true`. Новые правила выходят выключенными — см. [Политика версий](../readme.md#политика-версий).

| Правило                                | Причина                                                         |
| -------------------------------------- | --------------------------------------------------------------- |
| `punctuation.comma_before_conjunction` | ложные срабатывания на прямой речи и именах                     |
| `punctuation.period_at_end`            | неверно для фрагментов и пунктов списка                         |
| `nobr.initials_dots`                   | добавляет точки после любых инициалов, хотя нужны они не всегда |
| `nobr.nowrap_hyphen_short`             | срабатывает на любом коротком слове с дефисом                   |
| `nobr.nowrap_hyphen`                   | запрещает перенос всех слов с дефисом                           |
| `date.nowrap_day_range`                | узкая эвристика диапазона дат                                   |
| `hanging.quote`                        | требует поддержки в CSS и нужно не всегда                       |
| `hanging.bracket`                      | требует поддержки в CSS и нужно не всегда                       |
| `other.nbsp_in_nowrap`                 | заменяет обёртки nowrap неразрывными пробелами                  |
| `text.deduplicate_words`               | убирает намеренный повтор (`Тень Тень`)                         |

## 3. Вывод разметки

Имеет смысл только при `html: true`; при `html: false` каждый параметр деградирует или пропускается (см. [ниже](#5-мягкая-деградация-html-false)).

| Ключ         | Тип                                | По умолчанию | Эффект                                                                                                                                                  |
| ------------ | ---------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `paragraphs` | bool                               | `true`\*     | оборачивать абзацы в `<p>…</p>`                                                                                                                         |
| `autolink`   | bool                               | `true`       | голый URL/email → `<a href>`                                                                                                                            |
| `breakline`  | bool                               | `true`\*     | одиночный `\n` → `<br>`                                                                                                                                 |
| `nowrap`     | `'nobr'` \| `'span'`               | `'span'`     | элемент для неразрывных групп: `<span style="white-space:nowrap;">` или устаревший `<nobr>` для сред без поддержки стилей (например, почтовых клиентов) |
| `hanging`    | `'style'` \| `'class'` \| `'both'` | `'style'`    | режим вывода выравнивания: строчный `style`, `class="oa_…"` или оба. Само выравнивание включают `hanging.quote`/`hanging.bracket`                       |
| `prefix`     | `false` \| string                  | `false`      | префикс генерируемых классов `oa_*` (имеет значение при `hanging: 'class'`/`'both'`)                                                                    |

`paragraphs` и `breakline` размечают только текст вне элементов автора: внутри `<div>`, `<li>`, `<span>` и любого другого элемента переводы строк и пустые строки остаются как есть.

\* Для `format: 'markdown'` и `'frontmatter'` `paragraphs` и `breakline` по умолчанию **выключены**, даже при `html: true`: Markdown на входе и на выходе остаётся исходным текстом, а блочную разметку расставляет рендерер дальше по конвейеру. Строчная разметка (`nowrap`, автоссылки, оптическое выравнивание) при этом работает. Включить блочную обёртку можно явно: `render: { paragraphs: true }`.

`render.paragraphs`/`autolink`/`breakline` переопределяют правила группы `text`, только если явно заданы в конфигурации. `render.prefix` подставляется в атрибут `class` без экранирования, поэтому не должен содержать кавычку, угловую скобку, `&` или пробел; иначе — `MicroTypoConfigError`.

## 4. Матрица `html` × `entities`

Обе оси независимы; допустимы все четыре комбинации: обычный текст (по умолчанию), текст с сущностями, разметка с Unicode, разметка с сущностями.

```js
const text = 'Помню "Амбер" - его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.';

microtypo(text);
// 'Помню «Амбер» — его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { entities: true });
// 'Помню &laquo;Амбер&raquo;&nbsp;&mdash; его башни, и&nbsp;т.&nbsp;д. См.&nbsp;http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { html: true });
// '<p>Помню «Амбер» — его башни, <span style="white-space:nowrap;">и т. д.</span> См. <a href="http://amber.example">amber.example</a> тут.</p>\n\n<p>Корвин молчал.</p>'
```

`entities: true` кодирует только типографские глифы, которые движок создаёт сам. Буквальные `<`, `>`, `&` из ввода не затрагиваются — это не HTML-экранирование (см. [Безопасность](security.md)).

Для значений `json`/`yaml`/`toml` и заголовка `frontmatter` обе оси не действуют: они всегда выводятся без разметки и без именованных сущностей, чтобы остаться пригодными для повторного разбора. Текстовые узлы `xml` при `entities: true` получают числовые ссылки на символы (`&#8212;`, а не `&mdash;`).

## 5. Мягкая деградация (`html: false`)

Все преобразования на уровне глифов (кавычки, тире, неразрывные пробелы, многоточие, валюта, дроби, ×, ©…) выполняются и при `html: false`. Меняются только те, что без разметки невыразимы:

| Преобразование                           | `html: true`                                       | `html: false`                                        |
| ---------------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| nowrap словосочетания (`и т. д.`)        | `<span style="white-space:nowrap;">и т. д.</span>` | внутренние пробелы становятся неразрывными, без тега |
| nowrap токена без пробелов (IP, телефон) | `<span style="white-space:nowrap;">…</span>`       | остаётся как есть, без тега                          |
| autolink (голый URL/email)               | `<a href="…">…</a>`                                | обычный текст                                        |
| подстрочный/надстрочный индекс           | `<sub>…</sub>` / `<sup>…</sup>`                    | пропускается (нет текстового эквивалента)            |
| оптическое выравнивание                  | `<span style="…">`/`class="…"`                     | пропускается, даже если включено через `rules`       |
| абзацы и переносы строк                  | `<p>…</p>` / `<br>`\*                              | инвариант `\n\n` ниже, без тегов                     |

\* Кроме `format: 'markdown'` и `'frontmatter'`: там блочная обёртка выключена и при `html: true`.

## 6. Инвариант `\n\n`

Структура переносов нормализуется один раз, безусловно, до запуска любой группы правил: `\r\n` и `\r` → `\n`; три и более переносов подряд → ровно `\n\n`; одиночный `\n` и `\n\n` сохраняются.

```js
microtypo('a\n\n\n\nb', { html: false }); // 'a\n\nb'
microtypo('a\n\nb', { html: true }); // '<p>a</p>\n\n<p>b</p>'
```

Инвариант действует и при `html: false`, хотя группа `text` тогда пропускается: схлопывание — отдельный шаг движка, а не правило.
