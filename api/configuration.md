# Конфигурация

Один объект для `microtypo(text, config)` и `new MicroTypo(config)`: направление (`html`, `entities`, `input`, лимиты), правила (`rules`, `ruleGroups`) и вывод разметки (`render`).

```js
microtypo(text, {
  html: false,
  entities: false,
  input: 'text',
  maxInputLength: 30_000,
  maxProcessingMs: 5_000,

  rules: {
    quote: false,
    nbsp: false,
    'number.fraction': false,
    'abbr.*': false
  },

  render: {
    paragraphs: false,
    autolink: true,
    breakline: false,
    nowrap: 'span',
    hanging: 'style',
    prefix: false
  }
});
```

Неизвестный ключ или некорректное значение — `MicroTypoConfigError` при создании. Логические опции (`html`, `entities`, `input.math`, `render.paragraphs`, `render.autolink`, `render.breakline`, значения `rules`) принимают также `1`/`0` и строки `'on'`/`'off'`, `'true'`/`'false'`, `'1'`/`'0'` в нижнем регистре; `presets` — только `true`/`false`. Диагностика вызова (`changes`, `edits`, `trace`) — второй аргумент `process()`, см. [Расширение](extending.md#методы-экземпляра). CLI читает ту же конфигурацию из `.microtyporc.json`, см. [CLI](cli.md#приоритет-конфигурации).

В примерах неразрывные пробелы стоят там, где их ставит движок.

## 1. Направление

| Ключ              | Тип              | По умолчанию | Значение                                                                                           |
| ----------------- | ---------------- | ------------ | -------------------------------------------------------------------------------------------------- |
| `html`            | bool             | `false`      | `true` разрешает разметку: `<span>`, `<a>`, выравнивание, `<p>`, см. [раздел 3](#3-вывод-разметки) |
| `entities`        | bool             | `false`      | `true` — создаваемые глифы как именованные HTML-сущности; независим от `html`                      |
| `input`           | string \| object | `'text'`     | формат ввода и защита участков, см. [ниже](#input-строка-и-объект)                                 |
| `maxInputLength`  | int              | `30_000`     | от `0` до `5_000_000`; более длинный вход — `ERR_MICROTYPO_INPUT`                                  |
| `maxProcessingMs` | number           | `5_000`      | конечное ≥ 0, дроби допустимы; `0` отключает бюджет; превышение — `ERR_MICROTYPO_BUDGET`           |
| `presets`         | bool             | `true`       | `false` — без встроенных групп правил; защита и восстановление работают                            |
| `ruleGroups`      | array            | `[]`         | [группы как данные](extending.md#правила-как-данные)                                               |

`input`, `presets` и `ruleGroups` задаёт только конструктор: `applyOptions` с другим значением выбрасывает `MicroTypoConfigError`, группу после создания добавляет `registerRuleGroup`. Лимиты — в [Безопасности](security.md#лимиты).

## input: строка и объект

```js
microtypo(text, { input: 'markdown' }); // то же, что { input: { format: 'markdown' } }
microtypo(text, { input: { format: 'markdown', template: 'handlebars' } });
```

| Ключ           | Тип      | По умолчанию  | Значение                                                                                                                              |
| -------------- | -------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `format`       | string   | `'text'`      | `'text'` \| `'html'` \| `'plain'` \| `'markdown'` \| `'mdx'` \| `'json'` \| `'xml'` \| `'yaml'` \| `'toml'` \| `'frontmatter'`        |
| `template`     | string   | `'off'`       | [шаблонные разделители](#шаблонные-разделители): `'handlebars'`, `'mustache'`, `'twig'`, `'jinja'`, `'nunjucks'`, `'liquid'`, `'erb'` |
| `placeholders` | string   | `'all'`       | [заполнители локализации](#заполнители-локализации): `'icu'`, `'printf'`, `'interpolation'`, `'all'`, `'off'`                         |
| `pragmas`      | string   | `'microtypo'` | [комментарии-прагмы](#комментарии-прагмы): `'microtypo'`, `'off'`                                                                     |
| `math`         | bool     | `true`        | [формулы](#формулы-в-markdown) в Markdown, MDX и теле frontmatter                                                                     |
| `attributes`   | string[] | все пять      | [текстовые HTML-атрибуты](#текстовые-html-атрибуты): `alt`, `title`, `aria-label`, `placeholder`, `content`; `[]` — ни одного         |
| `fields`       | string[] | —             | `json`/`yaml`/`toml`/`frontmatter`: разрешённые [пути](#json)                                                                         |
| `exclude`      | string[] | —             | `json`/`yaml`/`toml`/`frontmatter`: исключённые [пути](#json)                                                                         |

Ведущий U+FEFF остаётся первым символом вывода; документ обрабатывается так, будто его нет.

Файловые форматы (`markdown`, `mdx`, `frontmatter`, `yaml`, `toml`, `json`, `xml`) сохраняют окончания строк и завершающие переводы строк. При смеси LF, CRLF и CR сохранившиеся границы остаются как были, новые, созданные правилами, получают самый частый вид (при равенстве — первый встретившийся); лишние пустые строки в прозе всё равно схлопываются. Защищённые блоки остаются байт-в-байт. `\n` внутри строки JSON — содержимое значения, а не граница строк. TOML принимает только LF и CRLF: одиночный CR — `MicroTypoInputError` (escape `\r` в basic string допустим).

Форматы данных типографируют только свой текст, не трогая структуру; значение — фрагмент, поэтому незакрытый тег или комментарий в нём защищает только себя.

### text и html

Форматы `'text'` и `'html'` равнозначны:

- HTML-комментарии сохраняются байт-в-байт; не типографируется содержимое `<pre>`, `<code>`, `<script>`, `<style>`, `<kbd>`, `<samp>`, `<var>`, `<tt>`, `<textarea>`, `<xmp>`, `<noembed>` и `<math>` (`<math/>` ничего не защищает). Список дополняет `addSafeTag(tag)`, см. [Расширение](extending.md#методы-экземпляра).
- Незакрытый комментарий или защищённый тег защищает текст до конца документа; тег без `>` до конца текста сохраняется целиком. `<p>` и `<br>` закрываются перед таким хвостом и в нём не ставятся.
- Текст `<title>` (RCDATA) типографируется без разметки: `&lt;b&gt;` остаётся текстом, nowrap даже при `html: true` даёт неразрывные пробелы, а не обёртку. В `<title>` внутри `<svg>` теги и комментарии — разметка: они сохраняются, кавычки их атрибутов не трогаются, проза вокруг типографируется (`<title>Глава <b>"Начало"</b> - да</title>` → `Глава <b>«Начало»</b> — да`).
- Границы тегов — по правилам HTML: имя начинается с `A–Z`/`a–z` (`a < b` и `<` перед кириллицей — текст), кавычка открывает значение только после `=`, тег кончается первой `>` вне кавычек, комментарий — первым `-->`. В Markdown и значениях форматов данных `<`, за которым до `>` идёт другой `<` вне кавычек, тега не открывает: `x<y` — текст.
- Значения атрибутов не типографируются, кроме выбранных в [`input.attributes`](#текстовые-html-атрибуты).
- Отступ в начале строки (пробелы и табуляции до первого непробельного символа; строка из одних пробелов — не отступ) сохраняется байт-в-байт, текст за ним типографируется, внутри строки пробелы схлопываются. Края документа обрезаются: пустые строки и замыкающие пробелы уходят, отступ первой непустой строки остаётся. При `html: true` отступ первой строки попадает внутрь `<p>`, отступ перед блочным тегом автора остаётся перед ним, а на следующих границах блока перевод строки становится пустой строкой и отступ уходит.

```js
microtypo('Строка\n    стих - тут\n\tещё  строка'); // 'Строка\n    стих — тут\n\tещё строка'
microtypo('<ul>\n  <li>Один</li>\n</ul>', { input: 'html' }); // без изменений
```

### Обычный текст

В `'plain'` `<` никогда не открывает разметку: `<code>`, `<script>`, `<notg>` и комментарии типографируются как текст. Стрелки, защита адресов, явных шаблонов и пользовательских блоков работают; края и отступы — как в `'text'`. Теги и сущности не создаются при любых `html`, `render`, `entities`, поэтому повторный проход не вкладывает теги. Исходные `<` не экранируются: экранируйте в месте вывода.

```js
microtypo('если a<b, то "c" - d', { input: 'plain' });
// 'если a<b, то «c» — d'
```

### Шаблонные разделители

`template` защищает байт-в-байт участки `{{ … }}`, `{% … %}`, `{# … #}`, `<% … %>` (по синтаксису движка) до любого правила, в любом `format`, включая строковые значения форматов данных. `}}` или `%}` внутри строкового литерала участок не закрывает. Тела `{% raw %}…{% endraw %}` (Liquid, Jinja, Nunjucks), `{% comment %}…{% endcomment %}` (Liquid) и `{{{{raw}}}}…{{{{/raw}}}}` (Handlebars) сохраняются вместе с разделителями, с маркерами `-` в Liquid и Jinja; незакрытый такой блок — до конца фрагмента. Разделители внутри ранее открытого кода или комментария принадлежат им.

```js
microtypo('Здравствуй, {{ name }}. Это "Амбер".', { input: { template: 'handlebars' } });
// 'Здравствуй, {{ name }}. Это «Амбер».'
```

### Заполнители локализации

`placeholders` защищает синтаксис заполнителей до правил, во всех форматах, включая выбранные строковые значения JSON, YAML и TOML; код и явно включённые шаблоны защищаются раньше.

- `'icu'` — `{name}`, аргументы с типом и стилем, `plural`, `selectordinal`, `select` с `offset:`, точными ветками и вложенными аргументами. Проза в ветках типографируется; `#` в ветке `plural` и участки в ASCII-апострофах по правилам ICU сохраняются.
- `'printf'` — `%s`, `%1$s`, `%@`, `%d`, ширина, точность, длина.
- `'interpolation'` — `${var}` без вложенных фигурных скобок.
- `'all'` — все три, по умолчанию.
- `'off'` — синтаксис заполнителей не защищается.

```js
microtypo('{n, plural, one {# день - текст} other {# дней - тексты}}');
// '{n, plural, one {# день — текст} other {# дней — тексты}}'
```

### Комментарии-прагмы

При `pragmas: 'microtypo'` (по умолчанию) участок от `<!-- microtypo-ignore-start -->` до `<!-- microtypo-ignore-end -->` сохраняется байт-в-байт вместе с комментариями. Вложенные участки закрываются попарно, незакрытый `start` действует до конца документа, одиночный `end` ничего не делает. `<!-- microtypo-ignore-file -->` возвращает весь документ как есть, включая BOM, заголовок frontmatter и переводы строк.

Прагмы читаются в `text`, `html`, `markdown`, `mdx` и теле `frontmatter`, но не в атрибутах, коде, защищённых элементах, шаблонах и метаданных frontmatter. В `plain`, `xml` и значениях JSON/YAML/TOML комментарии ничем не управляют.

```js
microtypo('<!-- microtypo-ignore-start -->Код - "текст"<!-- microtypo-ignore-end -->', {
  input: 'markdown'
});
// '<!-- microtypo-ignore-start -->Код - "текст"<!-- microtypo-ignore-end -->'
```

### Markdown

Типографируется проза; разметка CommonMark сохраняется байт-в-байт:

- ведущий заголовок, распознанный как во [front-matter](#front-matter): `---` (закрывается `---` или `...`) или `+++` (закрывается `+++`); без закрывающей строки заголовка нет. Блок за `---` — заголовок, только если, как в Pandoc, за открывающей строкой нет пустой, а первая строка, кроме комментариев `#`, — ключ YAML `имя:`; пустой `---\n---` — тоже заголовок. Иначе это линия и проза: `---\nГлава - первая\n---` типографируется. Значения заголовка типографирует формат `'frontmatter'`;
- ограждённые блоки (` ``` `, `~~~`) с информационной строкой;
- строки-ограждения контейнерных директив (Docusaurus, VitePress, remark-directive, markdown-it-container): три и более двоеточия в начале строки (после отступа до трёх пробелов и маркеров цитаты или списка) с именем и атрибутами до конца строки — `:::note{.x}`, `::: warning Заголовок`, `:::`. Строки между ними и двоеточия внутри строки — проза;
- код в строке с разделителем любой длины: закрывает серия той же длины, незакрытая серия — текст;
- строки-разделители таблиц GFM (чёрточки, необязательные двоеточия, столько же ячеек, сколько в заголовке); строки данных — проза;
- блоки с отступом (четыре пробела или табуляция) после пустой строки, начала документа или другой строки кода; иначе строка — продолжение абзаца или вложенный пункт и типографируется;
- HTML-комментарии. Незакрытый комментарий или `<pre>`, `<script>`, `<style>`, `<textarea>` в начале строки защищает текст до конца документа (внутри строки или кода — нет); закрытый такой тег — до своего закрывающего тега, остаток строки за ним типографируется; строка, где стоит только закрывающий тег другого из четырёх, защищается до конца строки;
- тег внутри кода или шаблонного выражения — текст: не открывает и не закрывает защиту и не образует пару с тегом снаружи. Обратная кавычка внутри такого элемента или комментария тоже текст: участок принадлежит тому, что открылось раньше;
- определения ссылок `[метка]: цель "заголовок"` (метка до 999 символов Unicode до схлопывания пробелов, без маркеров контейнера); определение сноски `[^1]: …` — проза;
- цель и заголовок в `](…)`, метка в `[текст][метка]`, маркеры списков (включая вложенные и `> - …`), жёсткий перенос из двух пробелов. Адрес в тексте ссылки (`[см. https://example.com](…)`, `[…][метка]`, `[…][]`) автоссылкой не становится;
- отступ в начале строки (два пробела держат абзац в пункте списка).

````js
microtypo('- Корвин - принц\n  - Рэндом ```a - b``` тут', { input: 'markdown' });
// '- Корвин — принц\n  - Рэндом ```a - b``` тут'
````

`html: true` даёт здесь только строчную разметку, см. [Вывод разметки](#3-вывод-разметки).

### Формулы в Markdown

`math: true` (по умолчанию) сохраняет байт-в-байт `$…$`, `$$…$$`, `\(…\)` и `\[…\]` в `markdown`, `mdx` и теле `frontmatter`; другие форматы опцию игнорируют. Одиночный `$` не открывает формулу перед пробелом, закрывающий не стоит после пробела или перед цифрой: `$5 и $10` — проза. `$…$` и `\(…\)` — в пределах одной физической строки, `$$…$$` и `\[…\]` допускают переносы. Экранированные и непарные разделители — текст. Код и ограды проверяются раньше формул; внутри открытого HTML-тега формула не открывается, а кавычки значений атрибутов её не открывают и не закрывают.

```js
microtypo('$a - b$ Корвин - принц', { input: 'markdown' });
// '$a - b$ Корвин — принц'
```

### MDX

`'mdx'` типографирует прозу как Markdown и сохраняет:

- ESM-блок с `import`/`export` в начале строки верхнего уровня — до пустой строки;
- выражения `{…}` с вложенными скобками, строками, шаблонными литералами, комментариями и регулярными выражениями;
- JSX-теги с атрибутами и выражениями, фрагменты `<>`/`</>`.

Текст между JSX-тегами типографируется. Регистр имени важен: `<Code>`, `<Pre>` — компоненты с прозой, `<code>`, `<pre>` защищены. Незавершённое выражение или тег защищает остаток блока до пустой строки или конца документа. Это терпимый сканер границ; код не выполняется и не проверяется. Формат `markdown` синтаксис MDX не защищает; JSX-атрибуты — код, `input.attributes` к ним не применяется.

```js
microtypo('<Box title="А - б">{label} Корвин - принц</Box>', { input: 'mdx' });
// '<Box title="А - б">{label} Корвин — принц</Box>'
```

### Текстовые HTML-атрибуты

`attributes` типографирует выбранные атрибуты (по умолчанию все пять: `alt`, `title`, `aria-label`, `placeholder`, `content`) в `text`, `html`, `markdown` и теле `frontmatter`; в `plain`, `mdx`, `xml` и значениях JSON/YAML/TOML не применяется. Список копируется при создании; не массив или неизвестное имя — `MicroTypoConfigError`.

```js
microtypo('<img alt="Корвин - принц" title="А - б" src="a-b.png">', {
  input: { format: 'html', attributes: ['alt'] }
});
// '<img alt="Корвин — принц" title="А - б" src="a-b.png">'
```

- `content` — только у `<meta>` с `name` или `property` из `description`, `og:title`, `og:description`, `twitter:title`, `twitter:description`.
- Имена тегов и атрибутов — без учёта регистра; из повторённых атрибутов берётся первый.
- В значении создаются только глифы, независимо от `html`, `entities` и `render`. Исходные ссылки на сущности сохраняются; новая кавычка, совпавшая с обрамляющей, пишется как `&#34;`/`&#39;`, в значении без кавычек символы, способные завершить атрибут, — числовыми ссылками. Краевые пробелы, остальные атрибуты и написание тега сохраняются.
- Атрибуты защищённых элементов, включая `addSafeTag`, не обрабатываются.

### JSON

Типографируются строковые значения; ключи и прочие значения не трогаются. Документ проверяется `JSON.parse` (ошибка — `MicroTypoInputError`), значения декодируются и экранируются через `JSON.parse`/`JSON.stringify`, так что вывод — валидный JSON.

```js
const src = '{"title":"Амбер - город","note":"Корвин - принц"}';

microtypo(src, { input: { format: 'json' } });
// '{"title":"Амбер — город","note":"Корвин — принц"}'

microtypo(src, { input: { format: 'json', fields: ['title'] } });
// '{"title":"Амбер — город","note":"Корвин - принц"}'
```

Пути в `fields`/`exclude`:

- без точки — последний сегмент на любой глубине: `'title'` совпадает с `title` и `posts.0.title`;
- с точками — полный путь посегментно, `*` — ровно один сегмент: `'posts.*.body'` совпадает с `posts.0.body`, но не с `posts.0.author.body`; пустой ключ — тоже сегмент: `'.title'` — это `title` внутри ключа `""`, не корневой;
- с ведущим `/` — [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) (`~1` → `/`, `~0` → `~`) по фактической структуре документа.

Точечный путь неоднозначен для ключей с `.` и числовых строк (`{"a.b": 1}` и `{"a": {"b": 1}}` дают `a.b`): это селектор удобства, а не граница безопасности.

### XML

Типографируются текстовые узлы; теги, атрибуты, комментарии, CDATA, инструкции обработки, DOCTYPE, ссылки на сущности (`&amp;`, `&#160;`, `&nbsp;`) и краевые пробелы документа сохраняются байт-в-байт. До обработки отклоняются (`MicroTypoInputError`) несовпадающая или незакрытая пара тегов, закрывающий тег с чем-либо кроме пробелов после имени, незакрытая кавычка атрибута и незавершённые `<!--`, `<![CDATA[`, `<?`, `<!DOCTYPE`.

```js
microtypo('<rss><channel><title>Амбер - вечный город</title></channel></rss>', {
  input: { format: 'xml' }
});
// '<rss><channel><title>Амбер — вечный город</title></channel></rss>'
```

- Кавычки подбираются с учётом сохранённых ссылок: `<p>«город &quot;<em>лес</em>&quot;“река”»</p>` → `<p>«город &quot;<em>лес</em>&quot;„река“»</p>`, `&quot;` не переписываются.
- `fields`/`exclude` принимаются, но ничего не делают.
- Поддерево элемента с `xml:space="preserve"` сохраняется целиком. Атрибут распознаётся по имени `xml:space` и значению после раскрытия числовых и пяти предопределённых ссылок; DTD не читается, поэтому `preserve` из объявления атрибута не учитывается.
- Защищённые теги действуют по имени элемента: `<code>`, `<script>` и прочие сохраняются, как в HTML, без возможности отключить.
- Имя элемента начинается с буквы Unicode, `_` или `:` (строже `NameStartChar`): `<😀>` — текст.

### YAML

Типографируются значения — в кавычках, голые и блочные; ключи (включая ключ явной пары `? … : …`), отступы, комментарии, маркеры `---`/`...` сохраняются байт-в-байт.

- Голый скаляр — только если это строка: числа, даты, время, логические значения и `null` (`100644`, `2001-12-14`, `190:20:30`, `no`, `~`) пропускаются, как и скаляр с якорем, тегом или переносом на следующую строку. Если в результате появился `: `, ` #`, перенос строки или индикатор в первой позиции, возвращается исходный вид.
- Блочные скаляры (`|`, `>`) — построчно; отступ и заголовок (`|-`, `|+`, `|2`) не трогаются.
- Якоря, псевдонимы и теги (`&x`, `*x`, `!!str`) не трогаются; строки с экранированием (`\` в двойных кавычках, `''` в одинарных) пропускаются.
- В коллекциях потока (`[…]`, `{…}`) типографируются скаляры в кавычках.
- Скаляр, чей результат содержит его обрамляющую кавычку (например, `”` или `&#34;`, свёрнутые к ASCII `"`), возвращается в исходном виде.

```js
microtypo('title: "Амбер - вечный город"\ntags: ["Тень - Арден"]', { input: { format: 'yaml' } });
// 'title: "Амбер — вечный город"\ntags: ["Тень — Арден"]'
```

`fields`/`exclude` — синтаксис [JSON](#json) с индексами последовательностей (`tags.0`, `court.king`). Ключ входит в путь как записан: `0x10:` — `/0x10`, `TRUE:` — `/TRUE`. Значение под ключом с нестроковым тегом (`!!int 0x10:`, `? !!null`) или под явным ключом не из одного скаляра в строку (`? |`, `? [a]`, `{ ? [a] : v }`) селекторы не выбирают и не исключают: оно типографируется только без `fields` и `exclude`. `%TAG` разрешает сокращённые теги ключей в пределах своего документа; повторный handle — `MicroTypoInputError`. Пустой ключ без тега — `/null` (в компактной паре последовательности — `/0/null`), строковый пустой ключ (`""`, `!!str`) — `/`. Незакрытая коллекция потока или лишнее содержимое после скаляра в кавычках — `MicroTypoInputError`.

### TOML

Типографируются строковые значения; ключи, комментарии и структура таблиц сохраняются байт-в-байт. Литеральные строки (`'…'`, `'''…'''`) типографируются всегда, базовые (`"…"`, `"""…"""`) — только без `\`. Строка остаётся исходной, если результат содержит её ограничитель (`"""` для многострочной). Строчные массивы и таблицы разбираются как структура.

```js
microtypo('title = "Амбер - вечный город"\ntags = ["Тень - Арден"]', { input: { format: 'toml' } });
// 'title = "Амбер — вечный город"\ntags = ["Тень — Арден"]'
```

`fields`/`exclude` — синтаксис [JSON](#json); `[[array-of-tables]]` и элементы строчного массива индексируются от 0. Незакрытые строка, заголовок таблицы или строчная коллекция, пустой сегмент ключа и лишнее содержимое после значения — `MicroTypoInputError`.

### Front-matter

Заголовок YAML или TOML и тело Markdown. Первая строка `---` открывает YAML (закрывается `---` или `...`), `+++` — TOML (закрывается `+++`). Заголовок типографируется как документ [YAML](#yaml)/[TOML](#toml) (к нему применяются `fields`/`exclude`), тело — как [Markdown](#markdown); строки-разделители и пустые строки перед телом сохраняются байт-в-байт. Без `---`/`+++` в первой строке весь документ — тело; открывающий разделитель без закрывающего — `MicroTypoInputError`.

```js
microtypo('---\ntitle: "Амбер - вечный город"\n---\n\nКорвин вернулся - домой.', {
  input: { format: 'frontmatter' }
});
// '---\ntitle: "Амбер — вечный город"\n---\n\nКорвин вернулся — домой.'
```

## 2. Правила

Все правила включены, кроме [выключенных по умолчанию](#правила-выключенные-по-умолчанию). Значение — логическое, ключ — одно из:

- имя группы (`quote`, `dash`, `symbol`, `punctuation`, `number`, `space`, `abbr`, `nobr`, `date`, `hanging`, `other`, `text`, без учёта регистра) — вся группа;
- [семантический набор](#семантические-наборы);
- идентификатор или маска: `number.fraction`, `abbr.*`, `quote.close`. Маска — до 64 символов и до четырёх `*`.

Каталог идентификаторов — в [Правилах](rules-reference.md). Селектор проверяется по каталогу: неизвестная группа или `'quote.typo'` — `MicroTypoConfigError`, маска принимается, если совпала хотя бы с одним правилом. Ключи применяются в порядке записи, последнее совпадение побеждает:

```js
microtypo(text, {
  rules: {
    'punctuation.*': false,
    'punctuation.ellipsis': true,
    'punctuation.period_at_end': true
  }
});
```

### Семантические наборы

Набор раскрывается на месте своего ключа: `{ units: false, 'abbr.nbsp_volt': true }` выключает единицы измерения, кроме вольт, обратный порядок выключает все.

| Набор      | Раскрывается в                                                                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nbsp`     | `nobr.nbsp_*` + `space.nbsp_*` + `abbr.nbsp_*` + `number.nbsp_*`                                                                                                                            |
| `emdash`   | `dash.em` + `dash.em_*` (`em_line_start`, `em_after_sentence`, `em_double_hyphen`, `em_triple_hyphen`; не `emphatic_particle`)                                                              |
| `endash`   | `dash.en_range` + `number.en_range`                                                                                                                                                         |
| `triads`   | `number.thin_space_triads` + `other.split_triads`                                                                                                                                           |
| `units`    | `abbr.nbsp_unit` + `abbr.nbsp_weight_unit` + `abbr.nbsp_volume_unit` + `abbr.nbsp_time_unit` + `abbr.nbsp_data_unit` + `abbr.nbsp_frequency_unit` + `abbr.nbsp_css_unit` + `abbr.nbsp_volt` |
| `currency` | `abbr.currency` + `abbr.nbsp_money_magnitude` + `abbr.nbsp_currency_prefix`                                                                                                                 |

### Настройки кавычек

`quote.nested` и `quote.inch` — настройки правила `quote.nested`, а не отдельные правила; оба включены.

| Ключ           | При `false`                                        |
| -------------- | -------------------------------------------------- |
| `quote.nested` | вложенные `«…»` не переписываются в `„…“`          |
| `quote.inch`   | `"` после цифры остаётся кавычкой, а не дюймом `″` |

### Правила, выключенные по умолчанию

`punctuation.comma_before_conjunction`, `punctuation.period_at_end`, `nobr.initials_dots`, `nobr.nowrap_hyphen_short`, `nobr.nowrap_hyphen`, `date.nowrap_day_range`, `hanging.quote`, `hanging.bracket` (требуют `html: true`), `other.nbsp_in_nowrap`, `text.deduplicate_words`. Поведение каждого — в [Правилах](rules-reference.md).

## 3. Вывод разметки

Действует при `html: true`; при `html: false` см. [раздел 5](#5-мягкая-деградация-html-false).

| Ключ         | Тип                                | По умолчанию | Эффект                                                                                                                        |
| ------------ | ---------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `paragraphs` | bool                               | `true`\*     | абзацы в `<p>…</p>`                                                                                                           |
| `autolink`   | bool                               | `true`       | голый URL/email → `<a href>`                                                                                                  |
| `breakline`  | bool                               | `true`\*     | одиночный `\n` → `<br>`                                                                                                       |
| `nowrap`     | `'nobr'` \| `'span'`               | `'span'`     | обёртка неразрывных групп: `<span style="white-space:nowrap;">` или `<nobr>` (для сред без стилей, например почты)            |
| `hanging`    | `'style'` \| `'class'` \| `'both'` | `'style'`    | вывод выравнивания: `style`, `class="oa_…"` или оба; само выравнивание включают `hanging.quote`/`hanging.bracket`             |
| `prefix`     | `false` \| string                  | `false`      | префикс классов `oa_*` при `hanging: 'class'`/`'both'`; кавычка, `<`, `>`, `&` или пробельный символ — `MicroTypoConfigError` |

\* Для `markdown`, `mdx` и `frontmatter` — `false`: блочную разметку ставит рендерер дальше по конвейеру; строчная (nowrap, автоссылки, выравнивание) работает.

`paragraphs`, `autolink` и `breakline` переключают правила `text.paragraphs`, `text.autolink` (вместе с `text.email`) и `text.breakline`, и только если заданы явно. `paragraphs` и `breakline` не трогают текст внутри элементов автора (`<div>`, `<li>`, `<span>` и др.).

`autolink` ставит ссылку и на адрес в скобках или сразу после `«`, `„`: `(https://example.com)` → `(<a href="https://example.com">example.com</a>)`; закрывающие скобка, кавычка, многоточие и знаки препинания остаются за ссылкой. `www.example.com` получает `href` со схемой `http://`, голая схема `https://` ссылкой не становится. `&amp;` или `&#38;` в адресе попадает в `href` одним `&amp;`.

Явные `paragraphs: true` и `breakline: true` в Markdown размечают только абзацы прозы верхнего уровня: `<p>` — вокруг абзаца между пустыми строками, `<br>` — на мягкий перенос внутри абзаца. Заголовки, код, списки, цитаты, таблицы, определения ссылок, линии, строки `:::`, HTML-блоки, ведущий заголовок YAML/TOML, абзацы в пунктах списка и цитатах и значения заголовка `frontmatter` не размечаются. Абзац, который без пустой строки прерывается блоком, получает `<br>`, но не `<p>` (строка с `<p>` открыла бы HTML-блок): `Строка\nСписок:\n- пункт` → `Строка<br>\nСписок:\n- пункт`. После жёсткого переноса (два пробела, `\`) или `<br>` автора второй `<br>` не ставится.

```js
microtypo('# Заголовок\n\nКорвин - принц\nРэндом\n\n- пункт', {
  input: 'markdown',
  html: true,
  render: { paragraphs: true, breakline: true }
});
// '# Заголовок\n\n<p>Корвин — принц<br>\nРэндом</p>\n\n- пункт'
```

## 4. Матрица `html` × `entities`

Оси независимы, допустимы все четыре сочетания.

```js
const text = 'Помню "Амбер" - его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.';

microtypo(text);
// 'Помню «Амбер» — его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { entities: true });
// 'Помню &laquo;Амбер&raquo;&nbsp;&mdash; его башни, и&nbsp;т.&nbsp;д. См.&nbsp;http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { html: true });
// '<p>Помню «Амбер» — его башни, <span style="white-space:nowrap;">и т. д.</span> См. <a href="http://amber.example">amber.example</a> тут.</p>\n\n<p>Корвин молчал.</p>'
```

`entities: true` кодирует только глифы, созданные движком; `<`, `>`, `&` из ввода не трогаются — это не HTML-экранирование, см. [Безопасность](security.md#не-средство-очистки-html).

В значениях `json`/`yaml`/`toml` и заголовке `frontmatter` обе оси не действуют: ни разметки, ни сущностей. В `xml` разметка не создаётся ни при каком `html`, а `entities: true` даёт числовые ссылки (`&#8212;`, а не `&mdash;`).

## 5. Мягкая деградация (`html: false`)

Глифы (кавычки, тире, неразрывные пробелы, многоточие, валюта, дроби, ×, ©…) ставятся и при `html: false`. Меняется только то, что требует разметки:

| Преобразование                           | `html: true`                                       | `html: false`                                        |
| ---------------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| nowrap словосочетания (`и т. д.`)        | `<span style="white-space:nowrap;">и т. д.</span>` | внутренние пробелы становятся неразрывными, без тега |
| nowrap токена без пробелов (IP, телефон) | `<span style="white-space:nowrap;">…</span>`       | остаётся как есть, без тега                          |
| autolink (голый URL/email)               | `<a href="…">…</a>`                                | обычный текст                                        |
| подстрочный/надстрочный индекс           | `<sub>…</sub>` / `<sup>…</sup>`                    | пропускается                                         |
| оптическое выравнивание                  | `<span style="…">`/`class="…"`                     | пропускается, даже если включено через `rules`       |
| абзацы и переносы строк                  | `<p>…</p>` / `<br>`\*                              | только [инвариант `\n\n`](#6-инвариант-nn)           |

\* Кроме `markdown`, `mdx` и `frontmatter`, см. [раздел 3](#3-вывод-разметки).

## 6. Инвариант `\n\n`

До любой группы правил и при любом `html` (это шаг движка, а не правило группы `text`) `\r\n` и `\r` становятся `\n`, а три и более переноса подряд — `\n\n`. Файловые форматы затем возвращают исходные окончания строк, см. [input](#input-строка-и-объект).

```js
microtypo('a\n\n\n\nb', { html: false }); // 'a\n\nb'
microtypo('a\n\nb', { html: true }); // '<p>a</p>\n\n<p>b</p>'
```
