# Конфигурация

Вся конфигурация — единый объект, передаваемый в `microtypo(text, config)` или `new MicroTypo(config)`. У неё три уровня, которые свободно сочетаются:

1. **Направление** — `html`, `entities`, `input` и лимиты защиты.
2. **Правила** — переключатели поверх каждого правила типографики.
3. **Вывод разметки** — как выдаётся разметка; имеет смысл только при `html: true`.

```js
microtypo(text, {
  html: false,
  entities: false,
  input: 'text',
  maxInputLength: 30_000,
  maxProcessingMs: 5_000,

  rules: {
    quote: false,
    nbsp: false,
    'number.fraction': false,
    'abbr.*': false
  },

  render: {
    paragraphs: false,
    autolink: true,
    breakline: false,
    nowrap: 'span',
    hanging: 'style',
    prefix: false
  }
});
```

## 1. Направление

| Ключ              | Тип              | По умолчанию | Значение                                                                                                       |
| ----------------- | ---------------- | ------------ | -------------------------------------------------------------------------------------------------------------- |
| `html`            | bool             | `false`      | главный переключатель разметки. `false` — только текст; `true` — `<span>`/`<a>`/выравнивание/`<p>` по уровню 3 |
| `entities`        | bool             | `false`      | `false` — обычный Unicode (`«`, `—`, `…`); `true` — именованные HTML-сущности. Независим от `html`             |
| `input`           | string \| object | `'text'`     | формат ввода и защита шаблонных разделителей — см. [ниже](#input-строка-и-объект)                              |
| `maxInputLength`  | int              | `30_000`     | отклонять более длинный ввод (`ERR_MICROTYPO_INPUT`); ограничен сверху `5_000_000`                             |
| `maxProcessingMs` | number           | `5_000`      | бюджет по времени между группами правил (`ERR_MICROTYPO_BUDGET`); `0` отключает                                |
| `presets`         | bool             | `true`       | `false` не регистрирует встроенные группы правил; слой защиты и восстановления продолжает работать             |

Некорректные значения выбрасывают `MicroTypoConfigError` при создании. О лимитах и ошибках — в [Безопасности](security.md).

## input: строка и объект

Строковая форма задаёт только формат:

```js
microtypo(text, { input: 'markdown' }); // то же, что { input: { format: 'markdown' } }
```

Объектная форма добавляет защиту шаблонных разделителей и выбор полей для форматов данных:

```js
microtypo(text, {
  input: {
    format: 'markdown',
    template: 'handlebars'
  }
});
```

| Ключ       | Тип      | По умолчанию | Значение                                                                                                           |
| ---------- | -------- | ------------ | ------------------------------------------------------------------------------------------------------------------ |
| `format`   | string   | `'text'`     | `'text'` \| `'html'` \| `'markdown'` \| `'json'` \| `'xml'` \| `'yaml'` \| `'toml'` \| `'frontmatter'`             |
| `template` | string   | `'off'`      | защита разделителей: `'off'`, `'handlebars'`, `'mustache'`, `'twig'`, `'jinja'`, `'nunjucks'`, `'liquid'`, `'erb'` |
| `fields`   | string[] | —            | только для `json`/`yaml`/`toml`/`frontmatter`: список разрешённых путей                                            |
| `exclude`  | string[] | —            | только для `json`/`yaml`/`toml`/`frontmatter`: список исключённых путей                                            |

Форматы `'text'` и `'html'` пока ведут себя одинаково: защищают строчные HTML-теги и сохраняют HTML-комментарии байт-в-байт. Форматы данных типографируют только свой текст, оставляя структуру нетронутой (см. соответствующие разделы ниже).

### Шаблонные разделители

`template` защищает байт-в-байт участки разделителей шаблонного движка (`{{ … }}`, `{% … %}`, `{# … #}`, `<% … %>` в зависимости от движка) до запуска любого правила, поэтому типографика затрагивает только текст вокруг них. Закрывающий разделитель ищется с учётом строк: `}}` или `%}` внутри строки-выражения в кавычках не закрывает участок раньше времени. Работает с любым `format`, включая строковые значения форматов данных.

```js
microtypo('Здравствуй, {{ name }}. Это "Амбер".', { input: { template: 'handlebars' } });
// 'Здравствуй, {{ name }}. Это «Амбер».'
```

### JSON

`input: { format: 'json' }` типографирует строковые **значения** документа, переписывая их на месте. Ключи и нестроковые значения не затрагиваются. Декодирование и повторное экранирование идут через `JSON.parse`/`JSON.stringify`, поэтому результат всегда остаётся валидным JSON. Весь документ предварительно проверяется `JSON.parse`: некорректный JSON выбрасывает `MicroTypoInputError`.

```js
const src = '{"title":"Амбер - город","note":"Корвин - принц"}';

microtypo(src, { input: { format: 'json' } });
// '{"title":"Амбер — город","note":"Корвин — принц"}'
```

По умолчанию типографируется каждое строковое значение. `fields` ограничивает выбор списком разрешённых путей, `exclude` убирает пути из выбранного:

```js
microtypo(src, { input: { format: 'json', fields: ['title'] } });
// '{"title":"Амбер — город","note":"Корвин - принц"}'
```

Синтаксис пути:

- **Образец без точки** совпадает со своим последним сегментом на любой глубине: `'title'` совпадает и с `title`, и с `posts.0.title`.
- **Образец с точками** совпадает с полным путём сегмент-в-сегмент; `*` — ровно один сегмент: `'posts.*.body'` совпадает с `posts.0.body`, но не с `posts.0.author.body`.
- **Образец с ведущим `/`** — это [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) (`/a/b`, с `~1`→`/` и `~0`→`~`): сопоставляется по фактической структуре документа, а не по строке пути.

Точечный путь неоднозначен, если ключ содержит `.` или является числовой строкой (`{"a.b": 1}` и `{"a": {"b": 1}}` дают один путь `a.b`). Это селектор удобства, а не граница безопасности для недоверенных данных: для строгого выбора полагайтесь на схему документа.

### XML

`input: { format: 'xml' }` типографирует **текстовые узлы** элементов. Всё остальное сохраняется байт-в-байт: теги, атрибуты, комментарии, секции CDATA, инструкции обработки, DOCTYPE и ссылки на сущности (`&amp;`, `&#160;`, `&nbsp;`). Документ не обрезается: ведущие и замыкающие пробелы сохраняются. Перед типографированием проход по стеку тегов отклоняет несовпадающую или незакрытую пару тегов, незакрытую кавычку атрибута и незавершённые XML-конструкции `<!--`, `<![CDATA[`, `<?` и `<!DOCTYPE` (`MicroTypoInputError`).

```js
const src = '<rss><channel><title>Амбер - вечный город</title></channel></rss>';

microtypo(src, { input: { format: 'xml' } });
// '<rss><channel><title>Амбер — вечный город</title></channel></rss>'
```

Для XML нет `fields`/`exclude`: грамматика сама определяет текстовые узлы, поэтому типографируется каждый. Ключи `fields`/`exclude` при `format: 'xml'` принимаются, но ничего не делают. Поддеревья элемента с `xml:space="preserve"` сохраняются целиком.

### YAML

`input: { format: 'yaml' }` типографирует **значения** заключённых в кавычки скаляров. Ключи и структура документа — отступы, комментарии, маркеры `---`/`...` — сохраняются байт-в-байт. Допустим только однострочный скаляр в кавычках без экранирования:

- голые скаляры (`title: Амбер`, без кавычек) пропускаются;
- блочные скаляры (`|`, `>`) пропускаются целиком;
- якоря, псевдонимы, теги (`&x`, `*x`, `!!str`) и коллекции потока (`{…}`, `[…]`) остаются нетронутыми;
- строка с любым экранированием (`\` в двойных кавычках, `''` в одинарных) не подходит.

Худший случай — недотипографирование, никогда не повреждение данных.

```js
microtypo('title: "Амбер - вечный город"\nslug: amber', { input: { format: 'yaml' } });
// 'title: "Амбер — вечный город"\nslug: amber'
```

`fields`/`exclude` используют тот же синтаксис пути, что и [JSON](#json), с индексами последовательности как сегментами. Незакрытая коллекция потока или лишнее содержимое после скаляра в кавычках выбрасывают `MicroTypoInputError`.

### TOML

`input: { format: 'toml' }` типографирует **значения** однострочных строк в кавычках. Ключи, комментарии (`#`) и структура таблиц сохраняются байт-в-байт:

- литеральные строки (`'…'`) подходят всегда;
- базовые строки (`"…"`) подходят без экранирования `\`;
- многострочные строки (`"""…"""`, `'''…'''`), строчные массивы и строчные таблицы пропускаются целиком.

```js
microtypo('title = "Амбер - вечный город"\nslug = "amber"', { input: { format: 'toml' } });
// 'title = "Амбер — вечный город"\nslug = "amber"'
```

`fields`/`exclude` — тот же синтаксис пути, что и [JSON](#json); каждое `[[array-of-tables]]` индексируется от 0. Незакрытый литерал, пустой сегмент ключа, незакрытый заголовок таблицы или лишнее содержимое после значения выбрасывают `MicroTypoInputError`.

### Front-matter

`input: { format: 'frontmatter' }` типографирует документ, открывающийся заголовком YAML или TOML, за которым идёт тело Markdown. Строка 1 задаёт грамматику: `---` открывает заголовок YAML (закрывается `---` или `...`), `+++` — заголовок TOML (закрывается `+++`). Заголовок типографируется как самостоятельный документ [YAML](#yaml) / [TOML](#toml) (`fields`/`exclude` применяются к нему), тело — как документ `format: 'markdown'`. Строки-разделители сохраняются байт-в-байт.

```js
const src = '---\ntitle: "Амбер - вечный город"\n---\n\nКорвин вернулся - домой.';

microtypo(src, { input: { format: 'frontmatter' } });
// '---\ntitle: "Амбер — вечный город"\n---\nКорвин вернулся — домой.'
```

Если строка 1 не `---` и не `+++`, заголовка нет и весь документ типографируется как тело Markdown. Открывающий разделитель без совпадающего закрывающего выбрасывает `MicroTypoInputError`: документ, заявивший заголовок и не предоставивший его, падает явно.

## 2. Правила

Все правила типографики включены по умолчанию (несколько — нет, см. [ниже](#правила-выключенные-по-умолчанию)). Каждый ключ — булев; три формы:

- **имя группы** — `quote`, `dash`, `symbol`, `punctuation`, `number`, `space`, `abbr`, `nobr`, `date`, `hanging`, `other`, `text` — переключает всю группу;
- **семантический набор** — раскрытие «одна концепция → несколько правил» (ниже);
- **точный идентификатор или маска** — `number.fraction`, `abbr.*`, `quote.close`.

Ключи применяются в порядке вставки, поэтому отключение маской с последующим точным включением работает как написано:

```js
microtypo(text, {
  rules: {
    'punctuation.*': false,
    'punctuation.ellipsis': true,
    'punctuation.period_at_end': true
  }
});
```

Имена групп регистронезависимы. Полный каталог идентификаторов — в [Правилах](rules-reference.md). Селектор проверяется по каталогу: `'quote.typo'` выбрасывает исключение, а `'quote.*'` принимается, если совпадает хотя бы с одним идентификатором.

### Семантические наборы

Набор получают только концепции, которые нельзя выразить одним `группа.правило`:

| Набор      | Раскрывается в                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `nbsp`     | `nobr.nbsp_*` + `space.nbsp_*` + `abbr.nbsp_*` + `number.nbsp_*`                                                                          |
| `emdash`   | `dash.em` + `dash.em_*` (`em_line_start`, `em_after_sentence`, `em_double_hyphen`; не `emphatic_particle`)                                |
| `endash`   | `dash.en_range` + `number.en_range`                                                                                                       |
| `triads`   | `number.thin_space_triads` + `other.split_triads`                                                                                         |
| `units`    | `abbr.nbsp_unit` + `abbr.nbsp_weight_unit` + `abbr.nbsp_data_unit` + `abbr.nbsp_frequency_unit` + `abbr.nbsp_css_unit` + `abbr.nbsp_volt` |
| `currency` | `abbr.currency` + `abbr.nbsp_money_magnitude` + `abbr.nbsp_currency_prefix`                                                               |

### Настройки кавычек

`quote.nested` и `quote.inch` — настройки, а не отдельные правила; оба читаются обработчиком `quote.nested`:

| Ключ           | По умолчанию | Эффект при `false`                                              |
| -------------- | ------------ | --------------------------------------------------------------- |
| `quote.nested` | вкл          | сохранять вложенные `«…»` вместо переписывания в `„…"`          |
| `quote.inch`   | вкл          | сохранять замыкающую `"` после цифр вместо преобразования в `″` |

### Правила, выключенные по умолчанию

Включаются через `rules: { 'группа.правило': true }`. `hanging.quote`/`hanging.bracket` дополнительно требуют `html: true`.

| Правило                                | Причина                                                 |
| -------------------------------------- | ------------------------------------------------------- |
| `punctuation.comma_before_conjunction` | лишние срабатывания на прямой речи и именах             |
| `punctuation.period_at_end`            | неверно для фрагментов и пунктов списка                 |
| `nobr.initials_dots`                   | предполагает, что голым инициалам всегда нужны точки    |
| `nobr.nowrap_hyphen_short`             | лишние срабатывания на любом коротком слове через дефис |
| `nobr.nowrap_hyphen`                   | широко отключает перенос слов по дефису                 |
| `date.nowrap_day_range`                | узкая эвристика диапазона дат                           |
| `hanging.quote`                        | требует подходящего CSS, нужно не всегда                |
| `hanging.bracket`                      | требует подходящего CSS, нужно не всегда                |
| `other.nbsp_in_nowrap`                 | переписывает существующие группировки nowrap            |
| `text.deduplicate_words`               | схлопывает намеренный повтор (`Тень Тень`)              |

## 3. Вывод разметки

Выбор выдаваемой разметки, имеет смысл только при `html: true`. При `html: false` каждый параметр деградирует или пропускается (см. [ниже](#5-мягкая-деградация-html-false)).

| Ключ         | Тип                                | По умолчанию | Эффект                                                                                                                                                          |
| ------------ | ---------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `paragraphs` | bool                               | `true`       | оборачивать абзацы в `<p>…</p>`                                                                                                                                 |
| `autolink`   | bool                               | `true`       | голый URL/email → `<a href>`                                                                                                                                    |
| `breakline`  | bool                               | `true`       | одиночный `\n` → `<br>`                                                                                                                                         |
| `nowrap`     | `'nobr'` \| `'span'`               | `'span'`     | элемент для группировок nowrap: современный `<span style="white-space:nowrap;">` (по умолчанию) или устаревший `<nobr>` для legacy-контекстов (например, email) |
| `hanging`    | `'style'` \| `'class'` \| `'both'` | `'style'`    | режим выдачи выравнивания: строчный `style`, `class="oa_…"` или оба. Само выравнивание включают `hanging.quote`/`hanging.bracket`                               |
| `prefix`     | `false` \| string                  | `false`      | префикс генерируемых классов `oa_*` (имеет значение при `hanging: 'class'`/`'both'`)                                                                            |

`render.paragraphs`/`autolink`/`breakline` переопределяют правила группы `text` только когда явно присутствуют в конфиге. `render.prefix` подставляется в атрибут `class` в сыром виде, поэтому не должен содержать кавычку, угловую скобку, `&` или пробел; иначе — `MicroTypoConfigError`.

## 4. Матрица `html` × `entities`

Обе оси независимы; валидны все четыре комбинации:

| `html` | `entities` | Результат                                              |
| ------ | ---------- | ------------------------------------------------------ |
| выкл   | выкл       | по умолчанию — обычный Unicode-текст, без единого тега |
| выкл   | вкл        | обычный текст, глифы как HTML-сущности                 |
| вкл    | выкл       | полная разметка, обычный Unicode                       |
| вкл    | вкл        | полная разметка, глифы как HTML-сущности               |

```js
const text = 'Помню "Амбер" - его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.';

microtypo(text);
// 'Помню «Амбер» — его башни, и т. д. См. http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { entities: true });
// 'Помню &laquo;Амбер&raquo;&nbsp;&mdash; его башни, и&nbsp;т.&nbsp;д. См. http://amber.example тут.\n\nКорвин молчал.'

microtypo(text, { html: true });
// '<p>Помню «Амбер» — его башни, <span style="white-space:nowrap;">и т. д.</span> См. <a href="http://amber.example">amber.example</a> тут.</p>\n\n<p>Корвин молчал.</p>'
```

`entities: true` кодирует только типографские глифы, которые движок создаёт сам. Буквальные `<`, `>`, `&` из ввода не затрагиваются — это не HTML-экранирование (см. [Безопасность](security.md)).

Форматы данных освобождены от обеих осей: значения `json`/`yaml`/`toml` и заголовка `frontmatter` всегда типографируются безопасно для данных — без разметки и без именованных сущностей, — чтобы значение оставалось годным для повторного разбора. Текстовые узлы `xml` при `entities: true` получают числовые ссылки на символы (`&#8212;`, а не `&mdash;`).

## 5. Мягкая деградация (`html: false`)

Каждое преобразование уровня глифов (кавычки, тире, склейка неразрывным пробелом, многоточие, валюта, дроби, ×, ©…) выполняется и при `html: false`. Меняют поведение только неустранимо разметочные преобразования:

| Преобразование                           | `html: true`                                       | `html: false`                                        |
| ---------------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| nowrap словосочетания (`и т. д.`)        | `<span style="white-space:nowrap;">и т. д.</span>` | внутренние пробелы становятся неразрывными, без тега |
| nowrap токена без пробелов (IP, телефон) | `<span style="white-space:nowrap;">…</span>`       | остаётся как есть, без тега                          |
| autolink (голый URL/email)               | `<a href="…">…</a>`                                | обычный текст                                        |
| подстрочный/надстрочный индекс           | `<sub>…</sub>` / `<sup>…</sup>`                    | пропускается (нет текстового эквивалента)            |
| оптическое выравнивание                  | `<span style="…">`/`class="…"`                     | пропускается, даже если включено через `rules`       |
| абзацы и переносы строк                  | `<p>…</p>` / `<br>`                                | инвариант `\n\n` ниже, без тегов                     |

## 6. Инвариант `\n\n`

Структура переносов нормализуется один раз, безусловно, до запуска любой группы правил:

- `\r\n` и `\r` → `\n`;
- три и более переносов подряд → ровно `\n\n`;
- одиночный `\n` и `\n\n` сохраняются.

```js
microtypo('a\n\n\n\nb', { html: false }); // 'a\n\nb'
microtypo('a\n\nb', { html: true }); // '<p>a</p>\n\n<p>b</p>'
```

Инвариант действует и при `html: false`, хотя группа `text` тогда пропускается: схлопывание — отдельный шаг движка, а не правило.

## Файл конфигурации (CLI)

CLI `microtypo` читает `.microtyporc.json` — JSON той же формы — автоматически обнаруживаемый обходом вверх от текущей директории либо переданный через `--config`. См. [CLI](cli.md).
