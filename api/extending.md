# Расширение

Экземпляр `MicroTypo` можно донастроить после создания. Все методы, кроме `process()` и дескрипторов, возвращают `this` и допускают цепочки.

## Методы экземпляра

- `addSafeTag(tag)` — защитить содержимое пользовательского HTML-тега от типографирования. Имя должно совпадать с `/^[a-zA-Z][a-zA-Z0-9-]*$/`, иначе `TypeError`. По умолчанию защищены `pre`, `code`, `script`, `style`, `kbd`, `samp`, `var`, `tt` и `textarea`. Список только дополняется: удалить из него имя нельзя.
- `addSafeBlock({ id, open, close, unsafeRegex? })` — защитить содержимое между пользовательскими разделителями. По умолчанию разделители экранируются как литералы; `unsafeRegex: true` трактует их как регулярные выражения (см. [Безопасность](security.md)).
- `setLayout('style' | 'class' | 'both')` — режим вывода оптического выравнивания (то же, что `render.hanging`). Любое другое значение выбрасывает `MicroTypoConfigError`.
- `setPrefix(prefix | true)` — префикс для генерируемых CSS-классов (`true` = `mt_`). Небезопасное значение выбрасывает `MicroTypoConfigError`.
- `applyOptions(config)` — применить дополнительную конфигурацию после создания; проверяется так же, как конфигурация конструктора. `input` и `presets` задаются только конструктором: от них зависит набор сканеров и групп правил, который собирается один раз. Попытка сменить их выбрасывает `MicroTypoConfigError`; повторная передача тех же значений допустима.
- `process(text, { changes? })` — типографировать текст. С `changes: true` возвращает `{ text, changes }` — места правок, см. [Использование](../readme.md#использование). Значение `changes`, отличное от булева, выбрасывает `MicroTypoConfigError`; прочие поля второго аргумента игнорируются.
- `getRuleGroup(name)` / `listRuleGroups()` — интроспекция: возвращают замороженные дескрипторы `{ name, title, builtin, rules: [{ id, defaultEnabled }] }`, а не живые группы.

```js
import { MicroTypo } from 'microtypo';

const typo = new MicroTypo({ html: true });
typo.addSafeTag('trump').setPrefix('mt_');
typo.process('<trump>"Козыри"</trump> и "Амбер"');
// '<p><trump>"Козыри"</trump> и «Амбер»</p>'
```

## `<notg>`

Встроенный способ снять типографику с куска текста без своего тега. Содержимое сохраняется байт-в-байт, но **сам элемент в выводе не остаётся**: он заменяется парой пустых маркеров `<span class="_notg_start"></span>` и `<span class="_notg_end"></span>` вокруг сохранённого текста. Это единственное место, где библиотека меняет структуру разметки, а не только текст в ней: маркеры показывают соседним правилам границу. Уберите или оформите их на стороне шаблона.

## Пользовательские группы правил

Подпуть `microtypo/define-rule` экспортирует `defineRuleGroup` для сборки собственной группы; она регистрируется через `registerRuleGroup(group, { name, position })`, где `position` — `'start'`, `'end'`, `'after:X'` или `'before:X'`. Порядок групп влияет на результат, поэтому невыполнимая позиция — неизвестное значение или ссылка на незарегистрированную группу — выбрасывает `MicroTypoConfigError` и не меняет экземпляр.

```js
import { defineRuleGroup } from 'microtypo/define-rule';

const group = defineRuleGroup({
  title: 'Козыри',
  rules: [{ id: 'trump', pattern: /Козырь/g, replacement: 'Козырь Амбера' }]
});
```

Правило — либо `{ id, pattern, replacement }`, где `pattern` — `RegExp` или массив, а `replacement` — строка, функция `(matchArgs, ctx) => string` или массив той же длины, что и `pattern`; либо `{ id, handler(ctx) => string }` для полного контроля (нельзя сочетать с `pattern`/`replacement`). Флаги: `enabled: false` — выключено по умолчанию, `cycled: true` — повторять до стабилизации (не более 100 итераций), `htmlOnly: true` — пропускать при `html: false`.

### Граница доверия

Пользовательская группа — это ваш код, и он исполняется с вашими правами: движок не песочница для JavaScript. Суженный `ctx` защищает не от этого кода, а от ошибки в нём.

Обработчик получает `text`, замороженный вид собственной группы, `html`, `tag()`, `iblock()`, `isOn()`, `tags.findByTagName` (функция-фильтр получает имя тега и признак самозакрытия `/>`), копии `layout` и `engineSettings`, снимок `onCycleLimit` и `checkBudget`. В `ctx` нет ни экземпляра движка, ни хранилищ, ни учёта подделок: обработчик не может их прочитать, пополнить, выключить или пометить свою группу встроенной. Всё, что группа возвращает или передаёт в `tag()` и `iblock()`, проходит один общий счёт: число вхождений заполнителя в результате не превышает числа его вхождений во входе группы плюс число раз, когда движок создал его для неё. Изменяемым остаётся `ctx.group.settings` — настройки той же самой группы. Чужие хранилища недостижимы: `findByTagName` отдаёт только идентификаторы, а подделанный заполнитель обнуляется до восстановления.

`defineRuleGroup` замораживает то, что возвращает, но не переданный объект `classes` — он остаётся вашим; `registerRuleGroup` снимает с него собственную копию, поэтому изменение после регистрации на вывод не влияет.

## Типизированные ошибки

Подпуть `microtypo/errors` экспортирует классы иерархии ошибок для проверок через `instanceof` — эквивалент проверке префикса `err.code?.startsWith('ERR_MICROTYPO')` (см. [Безопасность](security.md)):

```js
import { MicroTypoInputError } from 'microtypo/errors';

try {
  typo.process(input);
} catch (err) {
  if (err instanceof MicroTypoInputError) return input;
  throw err;
}
```

## Пустой движок

`new MicroTypo({ presets: false })` не регистрирует встроенные группы правил. Слой защиты и восстановления (URL/email, защищённые теги, экранирование зарезервированного PUA, нормализация глифов) продолжает работать, но правила не выполняются — основа для собственного набора групп.

```js
const typo = new MicroTypo({ presets: false });
typo.listRuleGroups(); // []
typo.process('"Амбер" остаётся как есть'); // '"Амбер" остаётся как есть'
```
