# Расширение

Экземпляр `MicroTypo` можно донастроить после создания. Все методы, кроме дескрипторов, возвращают `this` и допускают цепочки.

## Методы экземпляра

- `addSafeTag(tag)` — защитить содержимое пользовательского HTML-тега: такое содержимое не типографируется. Имя обязано совпадать с `/^[a-zA-Z][a-zA-Z0-9-]*$/`, иначе `TypeError`. По умолчанию защищены `pre`, `code`, `script`, `style`, `kbd`, `samp`, `var`, `tt` и `textarea`. Список только дополняется — убрать из него имя нечем.
- `addSafeBlock({ id, open, close, unsafeRegex? })` — защитить содержимое между пользовательскими разделителями. По умолчанию разделители экранируются как литералы; `unsafeRegex: true` трактует их как регулярные выражения (см. [Безопасность](security.md)).
- `setLayout('style' | 'class' | 'both')` — режим выдачи оптического выравнивания (то же, что `render.hanging`). Любое другое значение выбрасывает `MicroTypoConfigError`.
- `setPrefix(prefix | true)` — префикс для генерируемых CSS-классов (`true` = `mt_`). Небезопасное значение выбрасывает `MicroTypoConfigError`.
- `applyOptions(config)` — применить дополнительную конфигурацию после создания; валидируется как конфиг конструктора. `input` и `presets` задаются только конструктором: от них зависит набор сканеров и групп правил, который собирается один раз. Попытка сменить их выбрасывает `MicroTypoConfigError`; повторно назвать те же значения можно.
- `getRuleGroup(name)` / `listRuleGroups()` — интроспекция: возвращают замороженные дескрипторы `{ name, title, builtin, rules: [{ id, defaultEnabled }] }`, а не живые группы.

```js
import { MicroTypo } from 'microtypo';

const typo = new MicroTypo({ html: true });
typo.addSafeTag('trump').setPrefix('mt_');
typo.process('<trump>"Козыри"</trump> и "Амбер"');
// '<p><trump>"Козыри"</trump> и «Амбер»</p>'
```

## `<notg>`

Встроенный способ снять типографику с куска текста без своего тега. Содержимое сохраняется байт-в-байт, но **сам элемент в выводе не остаётся**: он заменяется парой пустых маркеров `<span class="_notg_start"></span>` и `<span class="_notg_end"></span>` вокруг сохранённого текста. Это единственное место, где библиотека переписывает структуру разметки, а не только текст в ней; маркеры нужны, чтобы соседние правила видели границу, и их полагается убрать или оформить на стороне шаблона.

## Пользовательские группы правил

Подпуть `microtypo/define-rule` экспортирует `defineRuleGroup` для сборки собственной группы; она регистрируется через `registerRuleGroup(group, { name, position })`, где `position` — `'start'`, `'end'`, `'after:X'` или `'before:X'`. Порядок групп нагружен, поэтому позиция, которую нельзя выполнить — неизвестное значение или ссылка на ещё не зарегистрированную группу, — выбрасывает `MicroTypoConfigError` и не меняет экземпляр.

```js
import { defineRuleGroup } from 'microtypo/define-rule';

const group = defineRuleGroup({
  title: 'Козыри',
  rules: [{ id: 'trump', pattern: /Козырь/g, replacement: 'Козырь Амбера' }]
});
```

Правило — либо `{ id, pattern, replacement }`, где `pattern` это `RegExp` или массив, а `replacement` — строка, функция `(matchArgs, ctx) => string` или массив той же длины, что и `pattern`; либо `{ id, handler(ctx) => string }` для полного контроля (взаимоисключающе с `pattern`/`replacement`). Флаги: `enabled: false` — выключено по умолчанию, `cycled: true` — повторять до стабилизации (не более 100 итераций), `htmlOnly: true` — пропускать при `html: false`.

### Что это за граница

Пользовательская группа — это ваш код, и он исполняется с вашими правами: движок не песочница для JavaScript и ею не притворяется. Суженный `ctx` защищает не от него, а от ошибки в нём.

Обработчик получает `text`, замороженный вид собственной группы, `html`, `tag()`, `iblock()`, `isOn()`, `tags.findByTagName`, копии `layout` и `engineSettings`, снимок `onCycleLimit` и `checkBudget`. В `ctx` нет экземпляра движка, нет хранилищ и нет учёта подделок — обработчик не может ни прочитать его, ни пополнить, ни выключить, ни пометить свою группу встроенной. Всё, что группа возвращает или передаёт в `tag()` и `iblock()`, проходит один общий счёт: заполнитель может стоять в результате столько раз, сколько его было во входе группы плюс сколько движок отчеканил для неё, и ни разу больше. Изменяемым остаётся `ctx.group.settings` — настройки той же самой группы. Чужие хранилища недостижимы: `findByTagName` отдаёт только идентификаторы, а подделанный заполнитель обнуляется до восстановления.

`defineRuleGroup` замораживает то, что возвращает, но не переданный объект `classes` — он остаётся вашим; `registerRuleGroup` снимает с него собственную копию, поэтому изменение после регистрации на вывод не влияет.

## Типизированные ошибки

Подпуть `microtypo/errors` экспортирует классы иерархии ошибок для проверок через `instanceof` — эквивалент проверке префикса `err.code?.startsWith('ERR_MICROTYPO')` (см. [Безопасность](security.md)):

```js
import { MicroTypoInputError } from 'microtypo/errors';

try {
  typo.process(input);
} catch (err) {
  if (err instanceof MicroTypoInputError) return input;
  throw err;
}
```

## Пустой движок

`new MicroTypo({ presets: false })` не регистрирует встроенные группы правил. Слой защиты и восстановления (URL/email, safe-теги, удаление зарезервированного PUA, нормализация глифов) продолжает работать, но типографика групп не выполняется — удобная основа для конвейера с нуля.

```js
const typo = new MicroTypo({ presets: false });
typo.listRuleGroups(); // []
typo.process('"Амбер" остаётся как есть'); // '"Амбер" остаётся как есть'
```
