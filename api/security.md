# Безопасность

## Не средство очистки HTML

Microtypo типографирует текст, но не экранирует и не удаляет HTML. Разметка (`<a>`, `<b>` и любая другая) сохраняется дословно:

```js
microtypo('<script>alert(1)</script>', { html: true });
// '<p><script>alert(1)</script></p>'
```

Если ввод недоверенный, а результат отображается как HTML, очищайте его отдельно (Sanitizer, DOMPurify). Движок отвечает только за собственную целостность против враждебного ввода, но не делает произвольный HTML безопасным для вывода.

## Модель угроз

Речь о целостности движка, а не о безопасности вывода.

| Угроза                                             | Защита                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Подделка заполнителей хранилища через ввод         | зарезервированный PUA удаляется из каждого входа до обработки                                 |
| Подделка хранилища URL/email                       | случайный разовый идентификатор на процесс в заполнителях                                     |
| ReDoS на состязательном вводе                      | лимит `maxInputLength` (основной), запасной бюджет `maxProcessingMs`, лимит циклов на правило |
| Исчерпание памяти                                  | лимит `maxInputLength` и предел числа записей в хранилище                                     |
| Пользовательское правило читает состояние движка   | обработчик получает суженный `ctx` — без ссылки на движок и без прямого доступа к хранилищам  |
| Пользовательское правило подменяет хук движка      | `onCycleLimit` фиксируется снимком в начале обработки                                         |
| Неполная структурная конструкция                   | XML-конструкции, Markdown-ссылки и шаблонные блоки защищаются целиком или отклоняются         |
| Блочный элемент внутри строчного (нарушение HTML5) | `<p>` вокруг блочных тегов снимается                                                          |
| Правка содержимого `<pre>`/`<code>`                | содержимое прячется в хранилище до запуска правил                                             |
| Рекурсивный `process()` портит хранилища           | повторный вход на том же экземпляре выбрасывает `MicroTypoInputError`                         |
| Выход `class`/`prefix` за пределы атрибута         | сгенерированные значения `class` экранируются, `prefix` отклоняет опасные символы             |

## Лимиты

Значения по умолчанию рассчитаны на враждебный ввод.

| Параметр          | По умолчанию | Эффект                                                                                  |
| ----------------- | ------------ | --------------------------------------------------------------------------------------- |
| `maxInputLength`  | `30_000`     | отклоняет более длинный ввод; в конфиге ограничен сверху `5_000_000`                    |
| `maxProcessingMs` | `5_000`      | бюджет по времени, проверяется между стадиями и в длительных сканерах; `0` — без лимита |
| Записи хранилища  | `100_000`    | предел накопления URL, email и тегов за один вызов                                      |
| Лимит циклов      | `100`        | предел повторных прогонов для правил с `cycled: true`                                   |

```js
const typo = new MicroTypo({ maxInputLength: 50_000, maxProcessingMs: 500 });
```

`maxInputLength` — основной механизм защиты от DoS. `maxProcessingMs` — запасной барьер: он проверяется между стадиями обработки и внутри части собственных сканеров, но не прерывает уже запущенное регулярное выражение или нативный разбор формата. Поэтому правило с квадратичными возвратами способно исчерпать бюджет до следующей проверки. Держите `maxInputLength` низким на публично доступных сервисах; повышение выше значения по умолчанию для внешних источников проверяйте нагрузочными тестами на своём вводе.

## Типизированные ошибки

Все классы наследуют `MicroTypoError extends Error` и несут `code`, `name` и необязательный `details`.

| Класс                  | Код                    | Когда выбрасывается                                                                                                 |
| ---------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `MicroTypoError`       | `ERR_MICROTYPO`        | базовый класс, напрямую не выбрасывается                                                                            |
| `MicroTypoConfigError` | `ERR_MICROTYPO_CONFIG` | некорректная конфигурация конструктора, вызова или `applyOptions()`                                                 |
| `MicroTypoInputError`  | `ERR_MICROTYPO_INPUT`  | ошибка ввода: тип, длина, переполнение хранилища, незавершённая XML-конструкция или превышение предела сканирования |
| `MicroTypoBudgetError` | `ERR_MICROTYPO_BUDGET` | обработка превысила `maxProcessingMs`                                                                               |

Проверяйте по общему префиксу кода:

```js
try {
  return typo.process(text);
} catch (err) {
  if (err.code?.startsWith('ERR_MICROTYPO')) return text;
  throw err;
}
```

## Параллельные вызовы

Состояние хранилищ сбрасывается на входе в `process()`, а однопоточный цикл событий JavaScript не чередует два синхронных вызова, поэтому один экземпляр `MicroTypo` можно переиспользовать между последовательными и асинхронно запланированными вызовами. Отклоняется только буквальная рекурсия: если обработчик пользовательского правила вызовет `process()` на том же экземпляре, движок выбросит `MicroTypoInputError` вместо повреждения состояния.

## Недоверенные пользовательские блоки

`addSafeBlock({ ..., unsafeRegex: true })` трактует разделители как регулярные выражения и пропускает экранирование, поэтому небрежный шаблон способен вызвать ReDoS. Проверяйте или изолируйте шаблоны, прежде чем открывать этот путь менее доверенным вызывающим. Без `unsafeRegex` разделители экранируются, и любая литеральная строка безопасна.

## Декодирование сущностей

Движок декодирует фиксированный набор HTML-сущностей и числовых ссылок в глиф за один проход и не пересканирует собственный вывод. У `&amp;`, `&lt;`, `&gt;` записи для декодирования нет — они сохраняются байт-в-байт: `Корвин &amp; Рэндом` проходит без изменений, а дважды закодированная последовательность вроде `&amp;trade;` никогда не декодируется частично. Поведение одинаково при `entities: true` и `entities: false`.
