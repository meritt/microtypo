# Безопасность

## Не средство очистки HTML

Движок пропускает исходный HTML, включая `<script>` с содержимым, а при `html: true` правила добавляют свою разметку:

```js
microtypo('<script>alert(1)</script>', { html: true });
// '<p><script>alert(1)</script></p>'
```

Недоверенный ввод, который выводится как HTML, очищайте отдельно (Sanitizer, DOMPurify). Движок отвечает только за собственную целостность на враждебном вводе.

## Модель угроз

| Угроза                                                          | Защита                                                                                                                                        |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Подделка заполнителей хранилища через ввод                      | символы U+E000, U+E001, U+E100, U+E101 из ввода на время обработки подменяются свободными символами PUA и возвращаются в вывод                |
| Подделка заполнителей URL/email/токенов                         | в заполнителе nonce из CSPRNG, новый на каждый `process()`; невосстановленный заполнитель в результате — `process()` возвращает вход как есть |
| ReDoS на состязательном вводе                                   | `maxInputLength` (основной), запасной бюджет `maxProcessingMs`, лимит циклов правила                                                          |
| Исчерпание памяти                                               | `maxInputLength` и предел записей в хранилище                                                                                                 |
| Пользовательское правило читает состояние движка                | суженный `ctx` без ссылки на движок и хранилища ([контекст](extending.md#контекст-обработчика))                                               |
| Пользовательское правило подделывает или размножает заполнитель | счёт заполнителей по входу группы; лишние удаляются                                                                                           |
| Пользовательское правило подменяет хук движка                   | `onCycleLimit` читается снимком в начале `process()`                                                                                          |
| Неполная структурная конструкция                                | XML-конструкции, Markdown-ссылки и шаблонные блоки защищаются целиком или отклоняются                                                         |
| Блочный элемент внутри `<p>`                                    | при `html: true` `<p>` вокруг блочных тегов снимается                                                                                         |
| Правка содержимого `<pre>`/`<code>`                             | содержимое прячется в хранилище до правил                                                                                                     |
| Синтетический `</p>` дописывает тег автора                      | абзацы и `<br>` закрываются перед незакрытым элементом, комментарием или недописанным тегом в конце документа                                 |
| Рекурсивный `process()` портит хранилища                        | повторный вход на том же экземпляре — `MicroTypoInputError`                                                                                   |
| Выход `class`/`prefix` за пределы атрибута                      | значения атрибутов экранируются, `prefix` отклоняет `"`, `<`, `>`, `&` и пробельные символы                                                   |
| Имя тега или атрибута в `ctx.tag()` как разметка                | имена — `/^[a-zA-Z][a-zA-Z0-9-]*$/`, иначе `MicroTypoConfigError`                                                                             |

## Ресурсы

### Лимиты

| Параметр          | По умолчанию | Эффект                                                                                                             |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------------------------------ |
| `maxInputLength`  | `30_000`     | вход длиннее (в единицах UTF-16) отклоняется до обработки (`ERR_MICROTYPO_INPUT`); в конфиге не больше `5_000_000` |
| `maxProcessingMs` | `5_000`      | бюджет времени одного вызова (`ERR_MICROTYPO_BUDGET`); `0` — без лимита                                            |
| Записи хранилища  | `100_000`    | одновременно в каждом хранилище; при переполнении — `ERR_MICROTYPO_INPUT`                                          |
| Лимит циклов      | `100`        | итераций правила с `cycled: true`                                                                                  |

```js
const typo = new MicroTypo({ maxInputLength: 50_000, maxProcessingMs: 500 });
```

Все хранилища очищаются в начале `process()`, хранилища URL, email и защищённых токенов — ещё и перед каждым фрагментом: например, два строковых значения JSON получают отдельные лимиты адресов.

`maxInputLength` — основная защита от DoS: он ограничивает и память, и работу каждого правила. CLI поднимает его до `5_000_000` ([CLI](cli.md)). На публичных сервисах держите его низким, а значение выше стандартного проверяйте нагрузочными тестами на своём вводе.

### Точность бюджета

`maxProcessingMs` сверяется между стадиями, после каждого вызова правила (в том числе при повторном чтении строчной разметки), после каждой итерации циклического правила и внутри долгих сканеров; у построения `changes` и `edits` свои проверки. Нативное регулярное выражение, `JSON.parse` и пользовательский обработчик не прерываются: превышение обнаруживается после их возврата. Замена `ctx.checkBudget` обработчиком внутренние проверки не отключает.

### Проверки сложности

- `pnpm lint:redos` ищет опасный перебор в регулярных выражениях встроенных правил и шаблонах адресов (попытка совпадения с одной позиции, со списком разрешённых предупреждений).
- `pnpm test:perf` проверяет рост времени с размером входа для правил, сканеров форматов, защиты и строчной разметки; например, миллион единиц UTF-16 HTML или Markdown должен обрабатываться быстрее восьми обработок 250 тысяч.
- `pnpm fuzz` проверяет, что каждый сгенерированный случай укладывается в отведённое время.

Стоимость пользовательских правил зависит от их реализации.

### Цена обработки

Полный вызов `process()` на документе около миллиона единиц UTF-16: Node.js 26.13.1, macOS 15.8.3, Intel Core i9-10910 3,60 ГГц; один прогревочный вызов, медиана пяти, худшая из двух серий; `maxInputLength: 1_000_000`, `maxProcessingMs: 0`. В `text` — абзацы с прямой речью, суммой и сокращением; в HTML и Markdown — с выделением и ссылкой; в JSON, YAML и TOML — списки коротких строк; в XML — элементы с текстом.

| Формат                   | Единиц UTF-16 | Вызов, мс |
| ------------------------ | ------------: | --------: |
| `text`                   |     1 000 000 |       222 |
| `text`, `html: true`     |     1 000 000 |       353 |
| `html`                   |       999 948 |       430 |
| `html`, `html: true`     |       999 948 |       652 |
| `markdown`               |       999 940 |       476 |
| `markdown`, `html: true` |       999 940 |       603 |
| `json`                   |       999 988 |     1 101 |
| `yaml`                   |       999 984 |     1 081 |
| `toml`                   |       999 948 |     1 061 |
| `xml`                    |       999 934 |       328 |

Средняя цена на единицу не задаёт верхнюю границу: для своего ввода измеряйте полный вызов.

## Типизированные ошибки

Классы экспортирует `microtypo/errors`. Все наследуют `MicroTypoError` (расширяет `Error`) и имеют `code`, `name` и необязательное `details`.

| Класс                  | Код                    | Когда                                                                                                                                                                                                                              |
| ---------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MicroTypoError`       | `ERR_MICROTYPO`        | базовый, напрямую не выбрасывается                                                                                                                                                                                                 |
| `MicroTypoConfigError` | `ERR_MICROTYPO_CONFIG` | некорректная конфигурация конструктора, `applyOptions()`, опций `process()`, методов экземпляра и групп правил как данных                                                                                                          |
| `MicroTypoInputError`  | `ERR_MICROTYPO_INPUT`  | не строка; длина; повторный вход; некорректный JSON, YAML, TOML, XML или front-matter; переполнение хранилища (`details.reason: 'capacity'`); предел сканирования ссылки или шаблона; нет свободного символа PUA для экранирования |
| `MicroTypoBudgetError` | `ERR_MICROTYPO_BUDGET` | превышен `maxProcessingMs`                                                                                                                                                                                                         |

Ошибки формы пользовательской группы, правила и имени в `addSafeTag()` — `TypeError`.

```js
import { MicroTypoInputError } from 'microtypo/errors';

try {
  return typo.process(text);
} catch (err) {
  if (err instanceof MicroTypoInputError) return text; // или err.code?.startsWith('ERR_MICROTYPO')
  throw err;
}
```

## Параллельные вызовы

`process()` синхронен и сбрасывает хранилища на входе, поэтому один экземпляр можно переиспользовать в последовательных и асинхронно запланированных вызовах. Отклоняется только рекурсия: `process()` того же экземпляра из обработчика правила выбрасывает `MicroTypoInputError`.

## Пользовательские образцы

Движок не песочница: пользовательская группа исполняется с правами вызывающего кода. Её образцы (`registerRuleGroup`, `ruleGroups`) и разделители `addSafeBlock({ unsafeRegex: true })` на ReDoS не проверяются, а бюджет сверяется только после возврата образца. Без `unsafeRegex` разделители экранируются, и любая строка безопасна. Недоверенные образцы проверяйте или изолируйте с внешним ограничением времени.

## Декодирование сущностей

Фиксированный набор именованных сущностей и числовых ссылок декодируется в глифы за один проход, без пересканирования вывода. Числовая ссылка декодируется в любой записи (`&#34;`, `&#034;`, `&#x22;`, `&#X22;`), если её кодовая точка есть в наборе. `&amp;`, `&lt;`, `&gt;` и их числовые ссылки (`&#38;`, `&#x26;`, `&#60;`, `&#62;`) сохраняются байт-в-байт: `Корвин &amp; Рэндом` не меняется, а `&amp;trade;` или `&amp;#x22;` не декодируются частично. Декодирование не зависит от `entities`. В формате `xml` ссылки — синтаксис документа и не декодируются.
